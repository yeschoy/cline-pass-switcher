# Go 版与当前项目的上游盯住策略比较

## Goal

对照 https://github.com/Hxjcc/cline-pass-switcher-go 与本项目的实际实现，解释账号与渠道「盯住」/粘性、失效与恢复、重试的差异，找出当前成功率偏低的可验证原因及可借鉴方案。交付详细中文分析；不修改业务代码、不触碰生产服务或凭据。

## Requirements

- 以固定提交版本、可定位的源码/测试/规范证据，对照请求身份提取、账号选择、渠道计划、发送参数、响应验证、成功记忆、TTL、健康/冷却、配额、重试及流式边界。
- 区分账号粘性与渠道粘性，也区分配置的渠道、上游实际渠道和可观测结果；覆盖不可钉住模型、失败前后状态、并发和重启语义。
- 把文档承诺与源码实际行为分开；不要把相关性或猜测写成造成低成功率的事实。
- 给出按收益/风险排序的可借鉴机制、当前项目已有机制、不能照搬之处和使用本地 mock 的验证/灰度指标方案。
- 不打印或检查生产密钥、用户数据；不改业务代码、配置、部署、生产状态。

## Acceptance Criteria

- [x] 提供两边版本标识和按维度的详细对照，关键结论有文件/行号证据（Go 仓库使用固定提交链接）。
- [x] 对成功率低给出可证实的代码级解释及待运行时数据验证的假设，明确哪些仍未知。
- [x] 提供可执行但未实施的优先级改进路线、反例/回退边界与测试建议。
- [x] 研究记录持久化于本任务的 `research/`，仅修改 Trellis 任务资料，不改业务代码。

## Scope

本次仅是只读研究与建议。用户明确要求「不要改代码」；后续实际改进须另行授权与规划。
