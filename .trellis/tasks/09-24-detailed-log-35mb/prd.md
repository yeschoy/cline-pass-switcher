# 详细日志正文上限与资源保护

## Goal

满足前一轮关于详细日志“提升到 35 MB”的目标。用户明确授权在**生产环境持久保存未脱敏的请求/响应正文，并通过远程管理网页查看**，以取消这些正文的昂贵脱敏工作；模型流量仍不可受诊断成败影响。此为安全合同的有意变更，仍在规划阶段，不得在权限隔离与验收方案获批前启用。

## Background

- 截图中的五条记录均为 `full · HTTP 200 / success`，列表状态为 `resource-limited`，模型/账号为 `[OMITTED: incomplete credential discovery]`。列表本身不能确定每条记录碰到哪个内存、工作量或输出限制。
- 当前 `lib/detailed-log-capture.js:5-6,315-383` 单正文原始上限 5 MiB，内部保留预算 64 MiB，并对原始与输出空间分别计费；还有独立的秘密/扫描/输出限制。用户现要求取消脱敏，并将共享保留预算提高到 512 MB；该预算不是精确 RSS 上限，单独改数字不保证截图病例可查看。

## Requirements

- 在不访问生产原始正文/凭据的前提下，利用列表、详情安全描述符和独立模拟测试区分长度截断、脱敏资源限制与凭据发现失败；不声称已知这些截图记录的具体触发分支。
- **已确认授权范围**：允许生产详细日志保存未经脱敏的客户端/上游请求与响应**正文**，并由远程网页管理员按需查看；单段目标 35 MB、共享保留预算目标 512 MB。此授权不扩展到普通 JSONL、服务日志、`metadata.json`、从账号配置主动复制 key/代理凭据或响应给模型客户端的诊断；**原始正文自身仍可能包含任何密钥，远程管理员可按需看见，不能声称已保护正文内秘密**。**已确认只对正文取消脱敏；Header 与列表元数据仍须隐藏敏感值**（可采用安全字段投影/省略，不因完整正文的脱敏成本再重复扫描正文）。
- 原始正文功能默认关闭；**先交付独立管理员密码鉴权及首次强制改密，废止客户端 API key 对管理 API 的访问**，之后才能允许生产开启原文详细日志。任何旧版本/旧客户端凭据不得访问未脱敏正文。**新未脱敏正文留存上限 48 小时**；已存在的脱敏历史记录仍维持现有 7 天/1 GiB 契约，单独不缩短。明确 MB/MiB、所有正文位置、内存/并发、磁盘上限；不把 512 MB 误称为 RSS 上限。
- 模型流量状态、响应字节、租约和普通日志须与详细日志开关、是否超限无关；超限仍安全、省略可见且可诊断。

## Acceptance Criteria

- 本地假凭据/假消息证明：未脱敏正文仅在明确启用且已独立管理员认证后可按需查看，未登录/仅持客户端 API key 无权访问；关闭模式与旧的已脱敏记录保持可读，普通日志、Header/元数据、服务输出不得跟随泄露。全文不进入测试 fixture 或提交历史中的真实值。
- 多个较大正文并发时内存/队列仍有可解释的硬边界；失败只损失诊断，不损失模型流量。
- 新原始正文在 48h 期限与既有磁盘容量边界内保留并能按期清理，旧的脱敏详情仍按旧保留规则可读；文档、管理 API 暴露的上限和 UI 说明一致。

## Scope assumptions for design review

- 将“35 MB/512 MB”明确按 35 MiB **每段正文**（客户端请求、上游尝试、最终响应）和 512 MiB **共享保留预算**规划；具体展示统一写明 MiB。用户允许生产远程查看未经脱敏的正文，包括正文里偶然包含的凭据，但不允许原始 Header/配置/普通日志扩散。
- 原始正文仅按需展示，页面显著警示，建议将其排除在外部备份外；服务只能保证自身 48h 过期，不承诺清理外部复制品。取消正文脱敏与调高预算不等于无上限，也不能追溯恢复旧省略记录。
