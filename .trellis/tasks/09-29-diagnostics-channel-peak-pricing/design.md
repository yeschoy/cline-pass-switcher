# Unified design — failure diagnostics, channel evidence, peak reference valuation

## Owners and scope

Keep one Trellis task and one feature branch. `server.js` continues to own request lifecycle, upstream routing, config normalization, statistics and `/api/statistics`; `DetailRoot`/`BodyCapture`/`DetailRedactor`/`DetailedLogStore` remain the sole detailed-content owner; `JsonlLogGroup` remains body-free. `public/index.html` extends the existing error-detail and model/provider panel controllers. Do not introduce a second statistics store, logging queue, pricing fetch, UI state store or transport. No production deployment is part of the code change. After acceptance, merge the verified feature branch into `main` without overwriting concurrent changes.

## 1. Error diagnostics

The reported gap has two distinct causes: profile selection is default-off (`server.js:59,4724`), and sanitized `error` currently holds only failed attempts' upstream response Header/body (`lib/detailed-log-capture.js:567-592`). Raw error holds failed *upstream* request/response, not the inbound user request. A linked ordinary error row points to an admitted attempt, not guaranteed durable publication; the UI must keep unavailable/expired/drop states honest.

Change the effective default to sanitized error-only capture for eligible chat aliases after admin initialization. Full capture keeps precedence; raw requires its independent explicit readiness gate. **User-approved one-time privacy migration:** `loadedConfig` is spread over defaults at `server.js:147-148`; an old persisted `errorDetailLogging:false` is indistinguishable from a deliberate opt-out. On first upgraded startup without a persisted migration marker, set error-only capture true even for old false; persist a bounded exact-version marker and the new boolean through the existing atomic config write, preserving original bytes on malformed/unreadable input or write failure. Subsequent startups and settings writes preserve an explicit false, including after restart. Reject invalid marker values rather than silently reapply migration. Document the fact that this overrides prior intentional disables and perform deployment privacy/backup review separately. Preserve manual settings' persist-first behavior and accurate GET/UI switch state.

Extend the same `DetailRoot` error profile, not ordinary JSONL, to retain bounded ingress Header and request-body observation and optionally a failed attempt's rewritten upstream request Header/body where useful. Distinguish ingress, upstream request and upstream response labels; no successful attempt response/body is retained solely because another attempt failed. Reuse group-wide secret discovery before producing **any** sanitized Header/body; header values may be sanitized by the existing redactor, never raw/copied into list summaries. Avoid extra body copies on the ordinary success path: cap diagnostic observation (existing 5 MiB/body), admission and retained payload budgets; release request/attempt copies on no-failure completion. Route validation/pre-attempt rejects may carry ingress diagnostic metadata with a truthful `no-upstream-attempt` state, but must not invent an upstream error row or response. SSE prelude/first error/post-start break, no-response, cancellation and failed-then-success paths keep current traffic/status/lease/RPM semantics. On capture/storage failure drop diagnostics fail-open and report only aggregate health, not secrets or fabricated per-request causes. Reuse authenticated on-demand details API and existing selected-row UI; preserve raw-mode allowlisted Header projection and its validator.

Security trade-off: enabling sanitized failure capture by default retains bounded prompt content, which is more sensitive than ordinary logs. The admin-only gate, seven-day/1-GiB limits, 0600 storage, sanitize-before-publish, explicit disable and default-off raw mode remain mandatory. Update operator docs/examples and spec for the changed default; require a deployment privacy/backup review before enabling on an existing server.

## 2. Upstream channel evidence and bounded live check

`parseRouting()` reads planner `provider_metadata.gateway.routing.finalProvider` and direct top-level `provider`; `commitStatistics()` allocates successful usage to a named Provider only when it equals the last real named successful attempt. An auto/unattributed/mismatched result is deliberately unknown. Thus target providers, a successful HTTP status or an upstream-only Header with an undocumented name cannot prove final channel. Existing safe production read-only evidence recorded a named `deepseek` target with `actualProvider:null`.

Before any actual server use, read backend deployment/security guidance, confirm current running version and the allowed remote access path, remaining safe account/RPM/expense bounds, and ensure no other task's budget is reused. Perform **at most one** small non-stream request using existing account-bound transport, deterministic small input/output, a short timeout and no intentional provider retries; do not print a key, raw body, arbitrary Header value or full config. Project only response status, bounded safe field names/enums, trustworthy claimed final Provider and whether the result matches the target. If an actual paid request cannot be bounded/authorized safely, stop and report unverified. Inspect whether a provider identity field is documented and trustworthy across JSON/SSE before changing `parseRouting()` or success attribution; do not map a target to actual by assumption. Tests remain local mock-only with temporary DATA_DIR.

## 3. Deterministic peak/off-peak reference estimate

The established price snapshot v1/v2 and v5 bounded minute buckets freeze existing low/high intervals; they are never backfilled. Freeze a new reference version/valuation contract for *future* successful requests only. Use `commitStatistics({ts})`'s terminal success UTC timestamp; UTC Mon–Fri [01:00,04:00) and [06:00,10:00) choose peak, all other times including weekends choose off-peak. User explicitly excludes Chinese-holiday overrides: a public-holiday weekday peak can be overestimated; label this simplified rule and non-billing reference nature in API/UI/docs. These hours do not prove ClinePass's actual tier; missing provider cannot be used as evidence of billing identity.

Compute one fixed-point BigInt amount at the existing `referenceValue`/`addReferenceValuation` seam after explicit input/output/cached-read validation (known zero is zero); only final success owns usage. Reuse versioned price snapshot and existing `{pricedRequests,lowPicoUsd,highPicoUsd,overflowFields}` cells: for a known-tier new request add the chosen amount to **both** bounds; old range-valued cells remain unequal. Mixed versions aggregate to a range if any historical interval remains; a single amount is displayed only when all included valued cells collapse, with priced-request and coverage caveats. Persist any schedule/version metadata with strict validation; never relabel old v1/v2 amounts as selected-tier values. API remains additive, UI uses existing `MODEL_PROVIDER_DATA` snapshot/generation and `mpMoney()` rather than a second estimator. No per-request all-bucket scan or calendar lookup: bounded UTC day/hour/minute plus two-tariff selection; query still uses existing bounded 1,440-minute scan.

Potential schema option to decide during implementation review: keep `STATISTICS_VERSION=5` if old/new price snapshots with a new deterministic version and strict validated metadata can coexist; otherwise add a targeted v6 migration preserving exact v1–v5 bytes/unknown semantics. No silent reinterpretation of old frozen intervals. Overflow and incomplete coverage remain null/partial, never `$0`. The independent community quota forecast stays untouched.

## Compatibility, rollback and observability

No credentials/raw bodies in API listings, ordinary logs, task artifacts, browser markup or service output. Old config false migrates exactly once per the approved decision; new explicit false persists after the marker. Preserve old price snapshots. A code rollback must not lose/read invalid new metadata: schema shape/price version compatibility and old-image read gate must be checked before any production release; do not deploy or claim old-image rollback is safe from local tests alone. Full project gate plus real-browser evidence for interactive diagnostic display/focus/narrow width; synthetic local perf/retention checks for default-on capture and per-request valuation.
