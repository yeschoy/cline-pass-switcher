# 执行计划：远程错误日志只读诊断

1. **连接前安全检查**
   - 验证仓库根目录、身份文件存在、权限为 `0600` 且已被 gitignore。
   - 使用 `BatchMode=yes` 和连接超时进行 SSH 只读连通性检查。

2. **生产基线采集**
   - 记录 UTC 时间、主机负载/内存/磁盘。
   - 读取 `cline-pass-console` 的运行状态、健康、镜像、启动时间、重启次数、OOM 标记与数据卷路径。
   - 读取部署元数据及有界容器启动日志，仅输出安全字段。

3. **日志安全聚合**
   - 在远程进程内只读解析请求/错误 JSONL，不复制原始日志到本地。
   - 分别统计全部保留区间、当前容器启动后和最近 24 小时。
   - 输出最终请求结果、失败请求 ID、上游失败尝试、状态/模型/账号/供应商/原因分布，以及无效行数量。
   - 验证错误条数与最终失败请求数之间的差异来源。

4. **交叉验证与根因归类**
   - 检查容器标准输出中的运行时异常。
   - 如可安全访问 NewAPI 对应渠道证据，则对时间窗口和状态做聚合关联。
   - 将原因归类为历史保留、旧版本误判、客户端取消、输入问题、账号/额度、上游服务、代理/网络或基础设施问题。

5. **结论与验证**
   - 形成带数量和时间证据的根因排序。
   - 给出最小处理建议和修复后验证指标；不执行任何修复、清理、重启或部署。

## 验证门槛

- 所有远程命令均为只读；检查前后容器 ID、启动时间、重启次数和配置文件哈希不因本任务改变。
- 输出中不得出现 Key、Authorization、Cookie、代理 URL 凭据、请求正文或响应正文。
- 结论必须同时说明“日志条数”和“最终失败请求数”，并标注分析时间范围。

## 停止条件

- 身份文件安全检查失败、SSH 认证失败或目标与规范不一致。
- 需要提权、写文件、修改配置或调用变更接口才能继续。
- 日志字段不足以支持结论且无法通过其他只读证据补足。
