# 排查远程服务器 cline-pass 切换器错误日志

## Goal

以只读方式检查生产服务器上的 cline-pass 切换器，确认当前大量错误日志的真实数量、来源和根因，并给出有证据、可验证的处理建议。

## Background

- 项目部署规范已固定生产目标：`ubuntu@167.114.158.4:49555`，远程目录 `/opt/cline-pass-switcher`，容器 `cline-pass-console`。
- 2026-09-14 的历史生产排查曾确认：服务器资源与容器健康正常；当时大量 502 中有 939 条属于流式请求完成后的误判，错误视图还按“上游失败尝试”计数，数量会高于最终失败请求数。
- 上述问题后来已在本地任务中修复，但历史 JSONL 按设计不会迁移或清空。因此当前界面的“大量错误”可能同时包含历史保留数据、统计口径差异和新的真实错误，必须以当前生产版本及时间范围重新核实，不能直接沿用旧结论。

## Requirements

1. 仅执行只读检查，不修改生产配置、数据、容器、镜像或日志。
2. 检查主机资源、容器状态、当前镜像/版本、启动时间与重启/OOM 情况，排除基础设施故障。
3. 对请求日志和错误日志按时间、最终状态、模型、账号、供应商、失败原因及请求 ID 做安全聚合，不输出账号 Key、代理 Key、请求正文或响应正文。
4. 区分最终请求失败、上游尝试失败、客户端取消、历史遗留记录和当前版本产生的新错误，避免将不同统计口径混为一谈。
5. 将 Switcher 记录与容器日志及可用的下游/NewAPI证据交叉验证，形成按证据强度排序的根因结论。
6. 给出针对根因的处理建议；任何修复、清理日志、重启或部署均不在本次授权范围内。

## Acceptance Criteria

- [ ] 报告明确检查时间点、日志覆盖范围、当前生产版本和容器健康状态。
- [ ] 报告给出错误总量与实际最终失败请求量，并解释二者是否因统计单位或历史保留而不同。
- [ ] 每个主要错误类别均有脱敏后的数量、时间分布和代表性证据。
- [ ] 根因结论明确区分“已确认”“高概率”和“尚需验证”，不把旧问题臆测为当前问题。
- [ ] 报告提供最小处理建议及验证方式，且整个排查过程未改变远程状态、未泄露凭据或业务正文。

## Out of Scope

- 修改代码、配置或生产数据。
- 清空或迁移历史日志。
- 重启容器、重新部署或执行修复。
