# 排查批量 content must not be empty 错误

## Goal

对齐当前生产环境 NewAPI 与 cline-pass-switcher 的日志，统计截图所示批量 HTTP 400 `content must not be empty` 的数量、时间分布和来源链路，确认直接触发原因，并解释为何现有页面看不到请求头和请求体。若确认详细日志将完整、无凭据的普通请求误判为不安全，则修复该误伤，同时保持凭据防泄漏和不完整输入的 fail-closed 边界。

## Background

- 用户截图显示 NewAPI 渠道 `71（cpc号池）` 在 `2026-09-17 15:43:01–15:43:02` 连续出现多条错误，模型为 `deepseek-v4-flash`，路径为 `/v1/chat/completions`。
- 经生产数据库核对，截图中的代表性 NewAPI 请求 ID 为 `202609170743020657752918268d9d6JKbO4xpJ`（截图 OCR 容易误加 `T`，并混淆字母 `O` 与数字 `0`）。
- 页面错误内容为 `status_code=400, …content must not be empty`；用户确认同类错误不止截图中的一条。
- 既有 2026-09-16 只读调查确认过同类错误由 Switcher 的消息内容前置校验产生，但本次必须以当前生产时间窗重新统计和归因，不能直接把历史结论当作当前证据。

## Requirements

1. 仅执行只读生产检查，不修改 NewAPI、Switcher、数据库、配置、容器、镜像或日志，不发送人为失败请求。
2. 统计当前容器启动以来以及截图时间簇内全部同类 400，给出数量、时间范围、峰值分布、模型、流式标志及可安全识别的调用主体聚类。
3. 使用截图请求 ID、时间、渠道和状态，将 NewAPI 日志、访问日志与 Switcher detailed manifest 做交叉验证；共享 ID 不存在时必须明确证据边界。
4. 检查 Switcher 直接触发点：请求是否在账号选择和上游调用前因 `messages[*].content` 校验失败，并区分它与上游 400/500、额度、账号和网络错误。
5. 解释 NewAPI 页面为何不展示请求头/请求体，以及 Switcher detailed logging 为何可能将整组 Header/正文标为 omitted，而不是将安全省略误判为日志丢失。
6. 不输出或复制 Authorization、Cookie、Key、代理凭据、请求正文、响应正文或普通 Header 值；仅使用安全元数据、结构枚举和不可逆指纹。
7. 形成可持久化的调查报告，按“已确认 / 高概率 / 尚需验证”给出根因和最小后续建议。
8. 使用本地合成请求确认普通提示词中的字面量 `\\uNNNN` / `\\xNN` 是否会在完整合法 JSON 中触发整组 `omitted-for-safety`；不得使用生产正文复现。
9. 若确认误伤，修复现有 `DetailRedactor`：完整普通文本中的字面转义不得导致整个请求/响应/Header 被清空；转义形式中出现或揭示的已知/结构化凭据仍必须从当前字符串及跨 Header/正文回显中移除。
10. 部分、截断、无效编码、无法完成凭据发现及资源上限场景继续 fail closed；详细日志不得改变业务请求/响应字节或状态。
11. 增加聚焦回归测试并运行完整测试套件；同步更新现行 logging code-spec。

## Acceptance Criteria

- [x] 报告注明检查时间、生产版本、容器状态和实际日志覆盖范围。
- [x] 给出同类错误总数、时间分布和截图时间簇数量，不只分析单条截图。
- [x] 代表性 NewAPI 请求 ID 能在允许的证据范围内与渠道 71、Switcher 400 manifest 关联。
- [x] 明确指出失败发生在客户端、NewAPI 转换、Switcher 前置校验或上游调用中的哪一层；无法最终定责时说明缺失证据。
- [x] 分别解释 NewAPI 和 Switcher 看不到请求头/请求体的机制，并区分“未采集”“安全省略”“已过保留期”和“UI 未展示”。
- [x] 报告不含任何凭据、正文或可逆敏感值，且检查前后远程服务状态未因本任务改变。
- [x] 无凭据的完整 JSON 包含普通字面 `\\uNNNN` / `\\xNN` 时，详细正文保持可读且 Header/响应不被整组省略。
- [x] 字面转义隐藏或回显已知/结构化凭据时，原始与解码形式均不出现在任何详细 metadata/body 投影中。
- [x] 部分/截断凭据、无效编码和 sanitizer 工作上限仍产生安全省略，聚焦测试及 `npm test` 通过。

## Out of Scope

- 修改空消息业务校验、调用方或 NewAPI。
- 将原始凭据、未经脱敏的 Header/正文写入任何日志。
- 放宽部分、截断、无效编码或资源耗尽场景的 fail-closed 边界。
- 开启/关闭生产详细日志、清空日志、重启容器或部署修复；生产部署需单独授权。
- 输出生产原始请求头、请求体或响应体。
