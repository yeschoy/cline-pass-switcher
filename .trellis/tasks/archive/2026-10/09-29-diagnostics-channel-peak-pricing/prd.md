# 完善错误诊断、渠道核验与峰谷计费

## Goal

在一个交付中改善失败请求的排障能力、核实上游真实渠道证据，并按可证明的时段计算成功请求的峰谷参考费用。

## Background

- 用户报告部分错误没有足够详情，明确希望在错误时查看用户发给本服务的请求体和请求头，以及上游响应头和响应体。
- 截图（2026-09-29 00:57）中 `cline-pass/glm-5.3-flash` 和 `cline-pass/deepseek-v4.1-flash` 的渠道显示“未知渠道”；这只证明控制台呈现未知，不能证明上游实际更换渠道。
- 截图（2026-09-29 00:59）中 `cline-pass/deepseek-v4.1-flash` 的参考费用为约 `$17.066–$34.132` 的“峰谷参考区间”；用户希望成功请求按适用时段计价再求和，并关注性能。
- 当前另有进行中的供应商/缓存核查任务；本任务沿用其中经确认的只读结论，但不变更其范围或状态。

## Confirmed Evidence

- `server.js:59,4724`：详细采集默认关闭且要求管理员已初始化。`lib/detailed-log-capture.js:439-457,486-493,567-592`：`full` 含入站与上游请求/响应，脱敏 `error` 只留失败 attempt 的响应头/体，`raw-error` 有失败的上游请求/响应但不等于入站用户原文。普通 JSONL 禁止存头值和正文；详细捕获须认证、受限、过期且失败时流量 fail-open（`.trellis/spec/backend/logging-guidelines.md`）。
- `server.js:2297-2310,2724-2731`：仅上游响应可信字段的实际最终 Provider 与真实成功具名 attempt 一致才归属渠道；否则成功用量记到未知渠道。先前只读核查曾发现目标 `deepseek`、HTTP 200 而 `actualProvider=null`，不能由目标推断网关内部实际供应商（`09-28-provider-plan-cache-regression/research/production-readonly-review.md`）。原只读任务的权限不涵盖付费验证。
- `server.js:935-996,2687-2732`：参考价格快照与 v5 统计分钟桶已存在，合格成功请求的两档金额被冻结并累计；当前没有按时间选档。`public/index.html:1510-1525` 显示峰谷区间。DeepSeek 官方价格页（https://api-docs.deepseek.com/quick_start/pricing/，2026-09-29 查阅）声明峰时为 UTC 周一至周五 01:00–04:00、06:00–10:00，法定节假日除外；**用户明确要求本项目简化规则忽略节假日**，因此在节假日的估值可能偏高。ClinePass 官方页（https://docs.cline.bot/getting-started/clinepass）说明其美元价格仅是包月配额的参考值，不是单独计费，不能把 DeepSeek 直连规则视为 ClinePass 实际账单证据。

## Unified Scope

同一个任务覆盖错误诊断、一次最小真实上游核验（具备安全条件才执行）及峰谷参考估值；分别测试后统一做跨层验收，不再建子任务。

## Requirements

- R1 错误诊断：用户确认错误详情默认自动采集，不依赖管理员预先打开开关；**现有持久化的旧 `errorDetailLogging: false` 首次升级也迁移为 true**，即便曾由管理员主动关闭；一次性迁移完成后，管理员再次关闭必须跨重启保持关闭。仅自动保存受限、脱敏的失败诊断，未脱敏原文仍保持独立显式开启和现有运行准入，不因本决定自动启用。区分用户入站请求、被改写的上游 attempt 请求、上游响应及下游终态；发生真实失败时，按安全、有限、管理员按需访问的详细诊断边界提供所需头和正文，并让普通错误行安全关联详情。无 attempt、无上游响应、SSE 中途失败、详情丢弃/过期应如实标明；失败后成功仍可查失败 attempt，取消不能伪装为错误。普通日志不保存头值或正文。
- R2 供应商核验：通过现有契约解释“未知渠道”；先核查运行版本与账户安全条件，再选择一个有边界的服务器账号作一次最小化、非流式、限输出请求，观察上游响应结构和响应头中的渠道证据，只留脱敏状态/字段结论，不披露凭据、不将真实载荷写入任务材料；不能确认安全条件则不调用。生产调用可能产生费用，且不能把目标、候选或猜测的渠道当成最终渠道。
- R3 峰谷计费：按成功终态的 UTC 时间，周一至周五 01:00–04:00、06:00–10:00（左闭右开）为峰时，其余时间及周六日为谷时；**不处理节假日例外**，不得将简化估值冒充供应商精确扣费。仅最终成功且用量完整一致的请求计价，单次冻结、汇总一次；历史区间不可偷偷重算。未知用量、价格和溢出不得伪装成精确金额；最终 Provider 未知仍可按已知模型的参考费率估值，但不能据此声称已知真实渠道或实际扣费。保持分钟桶有界工作量，避免每次请求扫描历史。所有金额为参考用量等值，不是 ClinePass 实际扣费。
- R4 保持现有路由、流式请求、取消、统计和诊断保密/保留策略；覆盖服务端、控制台、测试与可复用规范的受影响契约。开发和验证在独立功能分支进行，验收完成后再合并 `main`；不得提前在 `main` 开发、合并或部署。

## Acceptance Criteria

- [ ] A1 全新配置与旧版明确 `errorDetailLogging:false` 在升级后都无需管理员操作即可默认捕获脱敏失败诊断；迁移后手动关闭可跨重启保持关闭，未脱敏原文仍默认关闭且须独立准入；用临时 DATA_DIR/本地 mock 覆盖 HTTP 错误、200 错误包、SSE 首事件/中断、网络无响应、无 attempt 的本地拒绝、失败后成功、取消和详情缺失。管理员按需看到来源、截断/缺失状态和安全头/正文；普通日志、统计、未授权 API 不含请求/响应敏感原文，诊断故障不改变流量结果或租约/RPM。
- [ ] A2 对“未知渠道”给出可追溯的来源判断；有界真实核验若可安全执行，报告脱敏的上游响应/渠道证据及限制，若不可执行则明确未验证；仅真实可信字段可改变归属，覆盖 JSON/SSE/重试与历史未知。
- [ ] A3 峰谷模型的已知用量成功请求按成功终态 UTC 星期与分钟择档，并得到单次及累计参考金额；工作日两个峰时窗口的四个边界、周末、节假日仍按星期不作例外、未知用量/渠道、失败/取消/重试后成功、非峰谷模型、旧版本/重启及性能回归均有测试，未知保持未知。
- [ ] A4 不覆盖既有任务和操作数据；三项在同一任务中分别验证，再做跨层集成验收；功能分支验证通过后才合并 `main`。

## Operational Boundaries

- 用户知情选择升级时一次性覆盖旧版 `errorDetailLogging:false`，可能改变曾主动关闭的隐私状态；必须有持久迁移标记以保留升级后新的显式关闭，且生产启用仍须单独遵守部署/备份/回滚准入。
- 真正生产调用最多一次，先确认目标运行环境、现存鉴权和安全预算；只输出脱敏结论，不读取或输出凭据。不能安全执行时跳过并明确证据缺口。
- 上游不提供实际扣费档位或最终供应商时，不凭目标 Provider 或仅靠本地时间宣称已证实实际账单/渠道。忽略节假日会使工作日节假日峰窗参考估值相对官方时段偏高，UI/规范需显式标注。
