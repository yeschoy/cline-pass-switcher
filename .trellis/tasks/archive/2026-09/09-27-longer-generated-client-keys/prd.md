# 加长独立客户端密钥并改进一次性展示

## Goal

让管理员新建或轮换**独立客户端密钥**时拿到更长、能完整查看和复制的一次性密钥；不改变现有凭据的有效性或归属。

## Background

- 用户确认所指为“创建／轮换时自动生成的独立客户端密钥”，不是 Legacy 手填密钥或上游 Cline Pass API Key；希望生成值更长。
- 当前 `server.js` 的创建和轮换都生成 `cps_` 加 32 随机字节的十六进制文本，共 68 字符，已具备 256 位随机强度。`validateClientKeys` 允许独立密钥 16–256 字符；一次性弹窗为宽度有限的只读单行输入，视觉上只能看到局部。加长满足明确的可用性偏好，不意味着旧长度不安全。

## Requirements

- 后续创建与轮换均由服务端生成同一固定格式、更长的强随机密钥（方案建议共 100 字符）；保持现有 `cps_` 前缀、认证方式、唯一性与管理员认证边界，不新增不必要的“任意长度”配置。
- 一次性弹窗可完整查看长密钥并复制，复制失败仍可手动选择全文；关闭、导航、管理员会话失效后仍清除值，不把凭据放入列表、URL、localStorage、普通日志或研究产物。
- 已存在的独立密钥（包括 68 字符旧格式）继续有效；代码升级不得自动轮换、强制迁移或泄露。管理员明确轮换或撤销前原密钥保持有效；轮换不改变账号归属。Legacy 密钥及上游账号 Key 不在本子任务内。
- 不未经单独授权轮换生产密钥、修改生产配置或部署。

## Acceptance criteria

- [ ] 本地临时 `DATA_DIR` 下创建与轮换均返回符合新格式和长度的独立随机值，正常通过 Bearer/`X-Admin-Key` 模型认证；保留原有拒绝无权管理、旧密钥轮换后失效、账号归属不变等测试。
- [ ] 启动含既有 68 字符密钥的隔离配置时无需迁移，旧密钥仍可认证；列表/普通日志/公开元信息不新增明文暴露，管理写失败仍保留原文件字节与旧密钥。
- [ ] 控制台一次性弹窗在常见桌面和窄屏能完整查看、复制及手动选择长密钥；关闭／导航／401／刷新竞态清空，保留键盘焦点与可访问状态反馈。有自动化和真实浏览器验收。
