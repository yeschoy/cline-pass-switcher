# 优化账号密钥显隐与日志导航

## Goal

改善控制台中账号密钥与日志入口的可用性，使操作者能够按需查看账号密钥，并从页面顶部直接进入请求日志或错误日志。

## Background

- 账号设置抽屉位于 `public/index.html:233-240`；其中 `drawerKey` 是密码输入框，但没有显隐控件。
- “访问与安全”区域已有下游代理密钥显隐复选框，可沿用相同的明确显隐交互。
- 请求日志和错误日志当前共享 `public/index.html:215-219` 的页面下方卡片，通过 `logType` 选择类型；现有 `loadLogs(false)` 会重置游标。
- 用户明确拒绝“点击顶部按钮后滚动到页面下方”的快捷跳转方案；日志必须作为顶部导航可切换的独立板块呈现。
- 用户原先提出 Anthropic Messages API 与 OpenAI Responses API 适配，了解协议转换风险后决定本次不处理。

## Requirements

### R1 — 账号密钥显隐

- 在账号设置抽屉的 API Key 输入区域提供明确、可操作的“显示”控制，并允许再次隐藏。
- API Key 默认保持掩码，仅在操作者主动操作后显示明文。
- 每次打开账号设置（包括切换账号和重新打开同一账号）都恢复默认掩码，不能沿用之前的明文显示状态。
- 显隐状态只是界面状态，不计入草案脏检查，也不改变密钥保存、鉴权、日志脱敏或服务端信任边界。
- 控件使用关联标签和原生表单元素，支持键盘操作。

### R2 — 顶部板块导航

- 页面顶部提供可切换的控制台、请求日志和错误日志板块；日志不是滚动到主页面下方的锚点或快捷跳转。
- 激活日志板块后，主控制台内容不继续占据其上方空间，日志内容直接作为当前顶层板块呈现。
- 请求日志和错误日志在视觉与导航上是两个明确板块；底层可复用现有日志筛选、渲染和 API 状态，不能复制易漂移的业务逻辑。
- 切换请求/错误板块时选择对应类型、按该板块现有筛选条件加载第一页并重置所属游标，不得把另一类型的游标带入查询。
- 保留现有筛选、游标分页、详情安全渲染与“只清空当前类型”行为。
- 导航使用原生按钮，支持键盘操作，并明确标识当前激活板块。

## Acceptance Criteria

- [x] AC1：账号设置抽屉中的 API Key 默认掩码，可由操作者显式显示并再次隐藏。
- [x] AC2：切换账号或关闭后重新打开账号设置时，API Key 恢复为掩码；显隐切换不会触发未保存变更提示。
- [x] AC3：页面顶部存在可通过鼠标和键盘切换的“控制台”“请求日志”“错误日志”导航，并标识当前板块。
- [x] AC4：选择请求日志或错误日志后，不发生页面向下滚动；主控制台板块隐藏，对应日志直接成为当前顶层内容。
- [x] AC5：两个日志板块选择正确日志类型、重置各自查询游标，且现有筛选、下一页、详情安全转义和按当前类型清空行为保持不变。
- [x] AC6：相关静态 UI 契约、嵌入脚本语法检查、现有测试套件与 `git diff --check` 通过。
- [x] AC7：手动检查桌面及窄屏下的密钥显隐、键盘操作、焦点顺序和三个板块切换可用性。

## Out of Scope

- Anthropic Messages API（`POST /v1/messages`）与 OpenAI Responses API（`POST /v1/responses`）适配。
- 改变账号密钥的持久化方式、管理 API 返回结构或引入新的密钥存储系统。
- 新建独立 URL 页面或复制两套日志业务逻辑。
- 把原始请求/响应正文或其他敏感信息加入日志。
