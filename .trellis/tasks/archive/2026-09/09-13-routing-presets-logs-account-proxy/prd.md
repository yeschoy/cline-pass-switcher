# 调度预设、可观测日志与账号代理

## Goal

在保留现有 `single`、`roundrobin`、`sticky` 行为和安全边界的前提下，为账号池增加易用的策略预设、更多可预测的调度策略、可排障的请求/错误日志、账号级出站代理与请求头、账号备注、响应式管理界面和批量模型映射。

## Confirmed Facts

- 当前调度策略只有 `single | roundrobin | sticky`。
- 用户已批准首批新增 `least-connections`、`weighted-roundrobin`、`priority-failover`。
- 当前控制台直接暴露底层字段，缺少一键预设；本期需要提供会话稳定、最大吞吐、均匀分摊、按额度分摊、主备容灾、保守防封等预设。
- 当前 `metadata.json` 只保留最近 100 条混合请求历史；没有独立请求日志和错误日志。
- 当前历史已包含账号、供应商、尝试路径、账号动作和 `sessionSource`，但没有明确记录账号选择策略、HRW 首选/临时溢出及命中原因。
- 日志不得记录账号 key、代理认证值、原始会话值、消息正文、Cookie、Authorization 或敏感响应正文。
- 当前 Cline chat 传输使用 Node `http`/`https` 标准库，没有账号级出站代理能力，项目当前零第三方运行依赖。
- 该需求作为已部署首期账号路由任务之后的独立后续任务实施。

## Requirements

1. 增加 `least-connections`、`weighted-roundrobin`、`priority-failover` 三种账号调度策略，并保持旧策略配置兼容。
2. 账号新增 `weight` 与 `priority`：均为 1～100 的整数，`weight` 默认 1，`priority` 默认 100。`least-connections` 从有容量账号中选 `activeCount` 最少者并在并列时稳定轮询；`weighted-roundrobin` 按权重比例分配并跳过不可用或满载账号；`priority-failover` 优先选择数值最小的优先级，高优先级满载/冷却/封禁/禁用时立即使用下一优先级，同优先级内轮询。三种策略仅在全部候选满载时等待 `concurrencyWaitMs`；账号恢复后自动重新进入候选池。
3. 控制台提供一键策略预设，并在应用前展示将修改的字段；预设只允许修改 `accountMode`、`concurrencyWaitMs`、`maxConcurrent`、`weight`、`priority`、`accountErrorRules`，且必须逐项展示“当前值 → 新值”并由用户确认。预设不得修改账号名称、Key、启用状态、代理或任何全局/账号级模型路由；应用后保存为普通配置，允许继续手工调整且不得被后台重新覆盖。内置预设为：会话稳定（sticky/2000ms/429 冷却 30 分钟）、最大吞吐（least-connections/0ms/429 冷却 5 分钟）、均匀分摊（roundrobin/0ms/权重 1/优先级 100/429 冷却 30 分钟）、按额度分摊（weighted-roundrobin/0ms/初始权重 1/429 冷却 30 分钟）、主备容灾（priority-failover/0ms/首账号优先级 1、后续按 10 递增且最高 100/429 冷却 30 分钟）、保守防封（sticky/5000ms/每账号并发 1/401、403 封禁/429 冷却 60 分钟）。预设未列字段保持不变，错误规则按状态码合并。
4. 增加独立的请求日志和错误日志视图，使用独立滚动 JSONL 持久化而非继续写入 `metadata.json`。请求日志默认最多 50,000 条，错误日志默认最多 10,000 条，最长保留 30 天，两者总磁盘上限 100 MiB；任一限制先达到即清理最旧记录。支持分页、清空，以及按时间、请求 ID、模型、账号、调度策略、状态码、流式类型、目标/实际供应商、容量溢出和账号切换/错误筛选。
5. 每条请求日志至少记录时间、请求 ID、模型、流式与否、调度策略、会话来源类型、首选账号、实际账号、命中原因、是否容量溢出、目标/实际供应商、尝试路径、状态、耗时和账号处置动作。
6. 错误日志记录规范化状态、原始 HTTP 状态、错误类别、脱敏短原因、账号与供应商路径；不得保存敏感正文或凭据。
7. 增加账号级出站代理；默认不配置代理并保持直连。首期支持带可选用户名/密码认证的 `http://`、`https://`、`socks5://`、`socks5h://` URL。代理只作用于该账号发往 Cline Pass 的请求，不影响其他账号、公共目录抓取或管理 API。
8. 代理故障必须作为可观测的网络错误进入既有供应商/账号状态机，且不得泄漏代理凭据。配置了代理时禁止故障后自动回退直连，避免出口 IP 意外变化；控制台默认掩码代理认证值，并提供连通性测试。
9. 账号支持可选备注字段：最长 500 字符，允许换行但禁止其他控制字符。主表显示单行摘要，完整内容在右侧抽屉编辑；账号管理支持按名称或备注搜索。备注不得发送到上游，也不得进入请求日志、错误日志、响应头或诊断数据。后端 API、`config.json` 和 Web 控制台使用同一契约与校验范围。控制台使用统一的右侧“账号设置”抽屉编辑完整名称、备注、并发上限、权重、优先级、出站代理和自定义请求头，并展示账号专属模型路由摘要/入口；主表仅保留常用状态与设置入口，抽屉关闭时需处理未保存变更。
10. 调整控制台宽屏与窄屏布局：取消当前 1200px 过窄限制，在桌面宽屏下充分利用空间；账号名称列必须能完整展示常见邮箱式名称，并提供不会破坏移动端的横向滚动或响应式降级。
11. 支持账号级自定义上游请求头配置，不增加全局或模型级请求头。控制台通过右侧抽屉编辑；自定义头在客户端协议白名单头之后合并、在系统强制账号 Authorization 之前应用，但不得配置或覆盖 Authorization、Proxy-Authorization、Cookie、Host、Content-Length、逐跳 Header、会话/线程身份 Header、Attestation、Installation ID 或其他凭据/设备身份字段。日志只允许记录应用过的安全 Header 名称，不记录值；自定义头不得改变粘性会话识别。
12. 增加客户端模型名到 Cline Pass 模型名的映射：配置方向为 `客户端别名 -> cline-pass/* 实际模型`。控制台可从现有全部 `cline-pass/*` 模型批量生成去掉 `cline-pass/` 前缀的别名，并支持统一添加前缀/后缀及逐条编辑；重复别名或不存在的目标阻止保存。`/v1/models` 同时保留原始模型名并展示别名以兼容旧客户端。请求日志同时记录 `requestedModel` 与 `resolvedModel`，账号专属模型路由和供应商策略按 `resolvedModel` 执行。
13. 后端 API、`config.json` 和 Web 控制台对调度、日志、代理、备注、请求头和模型映射字段使用同一配置契约与校验范围。

## Acceptance Criteria

- [ ] 三种新增调度策略在可用、满载、冷却、封禁及恢复场景下行为符合定义，并有可运行回归测试。
- [ ] 预设能够一键应用、展示变更并持久化，刷新后不丢失；手动修改不会被预设后台覆盖。
- [ ] 请求日志能解释 sticky 命中账号、容量溢出和其他策略的选择原因。
- [ ] 错误日志能按时间、账号、模型、状态和请求 ID 定位一次失败及其尝试路径。
- [ ] 请求/错误日志按 JSONL 独立持久化，重启后保留；30 天、50,000/10,000 条和总计 100 MiB 限制均可执行验证，且支持分页、筛选和清空。
- [ ] 日志、API 响应和诊断信息不包含账号 key、代理认证值、原始会话值、消息正文或敏感响应内容。
- [ ] 未配置代理的旧账号继续直连；配置代理的账号分别通过 HTTP、HTTPS、SOCKS5 或 SOCKS5H 出站，其他账号保持直连；代理不可用时错误可诊断且不会回退直连。
- [ ] 账号备注可编辑、持久化并在刷新后保留，且不影响账号稳定 ID、路由或代理行为。
- [ ] 宽屏控制台不再局限于 1200px，常见邮箱式账号名称可完整查看；窄屏仍可操作且不挤坏表格。
- [ ] 自定义请求头按确认的作用域生效，危险 Header 无法配置或覆盖，且不会改变粘性会话识别与敏感信息日志边界。
- [ ] 模型别名批量生成、编辑、冲突校验和请求改写生效；`/v1/models` 同时展示别名与原始模型，日志可关联请求模型与实际模型。
- [ ] 旧配置无需修改即可继续运行。

## Out of Scope

- 基于长期机器学习或不可解释评分的自适应调度。
- TLS/JA3、设备指纹、Cookie 或 Attestation 伪造。
- 记录请求消息正文、原始会话标识或完整上游错误响应。
