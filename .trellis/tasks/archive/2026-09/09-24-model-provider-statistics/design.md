# Model / provider statistics and reference valuation — planning draft

## Data sources and identities

The existing `/api/statistics` has per-resolved-model recent-24h request/explicit usage aggregates; provider-model rolling success samples live in the existing health projection. Extend the *same* statistics finalizer and bounded minute-cell owner for **unambiguously attributed** final successful usage: one model request contributes its final usage once; only a unique named successful final attempt contributes to that Provider. A failed retry contributes a Provider health sample but no usage; `auto`/unattributed final usage remains in an explicit unknown-Provider bucket, never inferred from configured preference or distributed over attempts. Display final-model request success and Provider direct-health success samples with distinct denominators/coverage; cache Token ratio and cache-hit request rate use their own explicit known-denominators. Missing usage is unknown and explicit zero is zero.

## Official reference prices

Use a frozen internal snapshot of the ClinePass reference table at https://docs.cline.bot/getting-started/clinepass, identified by project version, collection date, model ID and USD-per-1M-token input/output/cached-read rates. The page has **no official price effective date**: label it unknown, never relabel the collection date. It is *not* what $9.99/month subscribers are additionally billed. Initial priced scope: `cline-pass/kimi-k3` and `cline-pass/glm-5.3` use one fixed price; `cline-pass/deepseek-v4-flash` and `cline-pass/deepseek-v4-pro` use both official peak/off-peak rates to produce a **labelled lower–upper reference range**, never a guessed tier. Other models remain visible for statistics but have unpriced reference cost until supported. The official rates and evidence are frozen in `research/official-pricing-and-usage.md`; no live pricing HTTP fetch. All four selected models list Cached Write as `—` in this snapshot; future cached-write-priced models need an explicit write count and cannot borrow cached-read or total tokens.

A valuated request must have explicit nonnegative input/output/cached-read counts, with `cachedRead <= input`; compute uncached input, cached read and output against each rate tier. Missing/invalid usage, ambiguous attribution for a Provider row, unsupported model/tier or inconsistent counts produce `不可计算`, never $0. Compute with decimal rate coefficients and BigInt/fixed-point picodollars before admitting a safe bounded aggregate; overflow is `null` with coverage, not wrap/zero. Freeze per-request valuation under a bounded *version-keyed* cell in the existing statistics minute bucket; a newer published table version adds new cells without revaluing old records. Retain at most a bounded number of versions/cells with truthful loss coverage. Aggregated model/Provider ranges sum frozen low/high values and expose version/source/collection dates (possibly multiple versions), no secret request body or actual billing claim.

## UI/API

Add a new read-only top-level section after “详细日志” in the production inline script, reusing `api()` and feature-owned query generation/abort controller. Extend the authenticated `/api/statistics` response additively with bounded 24h model rows, nested named Provider and explicit unknown-Provider rows, usage/health/valuation coverage and price-version facts. Escape every server value; native button/table and horizontally scrolling narrow view, focus/keyboard/live status. Money columns say `参考用量等值（USD），非实际扣费` and, for DeepSeek, `峰谷参考区间`; missing tariff/usage or inconsistent input/cached-read gives `不可计算`, not $0. The price source URL, internal version/collection date and unknown official effective date are visible. Search/filter/redraw/navigation cannot overwrite account/raw/error drafts or stale newer section reads.

## Compatibility

Preserve existing `/api/statistics` top-level fields and persisted statistic v1–v4 via explicit v5 migration with empty provider-usage/valuation cells and independent tracking-start/loss coverage. First post-upgrade Provider history is incomplete; no backfill from ordinary logs or old model totals. The model-success/Provider-health owners remain unchanged, and alias requests count only under resolved model. Bound the new minute cells and historical price versions independently. No second statistics store, billing HTTP fetch, frontend toolchain, dependency, production data or paid upstream.
