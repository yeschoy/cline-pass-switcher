# 增加模型缓存统计并修正展示

## Goal

在模型与账号控制台中提供可信、覆盖明确的缓存和健康摘要，修正“上游数 0”的误导，并精简额度窗口展示。

## Background

- 当前统计只有全局和按账号聚合，没有按模型聚合。
- 用户已确认每模型只显示最近 24 小时缓存 Token 占比，不显示请求命中率。
- 截图中的 `0` 是 `meta.upstreams.length`；planner 探测保存了 `finalProvider` 却未纳入列表，harvest 也只解析字符串错误，因此“0”不代表没有实际 provider。
- 账号主表仍按名称读取累计请求数，无法可靠支持重复名称；现有健康/统计投影已按稳定 ID 存在。
- 额度列同时显示已用和剩余，用户要求只保留剩余百分比。

## Requirements

### R1 — 模型 24h 缓存 Token 占比

- 按解析后的实际模型 ID 聚合聊天请求，别名不得拆分统计。
- 只统计上游明确提供的 input/cache usage；比例为缓存输入 Token / 输入 Token。
- API 和 UI 同时提供覆盖请求数、缓存 Token、输入 Token、比例及滚动窗口覆盖状态。
- 缺失 usage、分母为零、迁移后窗口尚未覆盖、计数溢出与已知 0 必须保持可区分。
- 管理/probe/test/catalog/quota 请求不得进入模型统计。

### R2 — 上游发现语义

- 成功探测观察到的 `finalProvider` 纳入已知 provider 集合。
- harvest 兼容字符串及结构化错误 envelope，只接受严格 provider slug，不保留原始错误体。
- UI 把未探测、发现失败和已知数量分开，不再把未知显示为 0。
- 发现不等于校验；未校验 provider 不显示为已验证可用。

### R3 — 账号主表摘要

- 每个账号按稳定 ID 显示最近 24h 缓存 Token 占比、健康状态/评分、24h 失败数和累计失败数。
- 重命名、重复名称、搜索和草稿编辑不得串统计。
- 统计只读，不改变完整账号保存、批量选择、抽屉或调度草稿。

### R4 — 额度去重

- 5 小时、每周、每月窗口只显示剩余百分比和重置时间。
- 0%/100%、未知、部分、失败、过期、禁用及预测算法保持原语义。

## Acceptance Criteria

- [x] 模型表每行显示最近 24h 缓存 Token 占比和覆盖请求数，不显示请求命中率。
- [x] 流式最终 usage、非流式、provider 重试、账号替换、失败、容量拒绝和取消均保持模型统计 exactly-once。
- [x] v1 统计元数据安全迁移；旧 24h 无模型归因时明确标记窗口尚未完整覆盖，不伪造 0。
- [x] 已知 `finalProvider` 时不再显示“上游数 0”；发现失败显示为未知/未发现。
- [x] 账号主表摘要按 ID 对齐，并保留全部本地草稿。
- [x] 额度列只显示剩余百分比与重置时间，预测与路由不变。
- [ ] integration、UI/VM、完整项目门禁已通过；真实浏览器桌面/窄屏检查因本机 browser binary/Accessibility 基础设施阻塞而未验证，见 `research/verification.md`。

## Out of Scope

- 不改变缓存池、账号选择、健康评分或额度预测算法。
- 不从普通日志反算统计。
- 不改变 provider 可用性校验规则或自动触发额外网络探测。
