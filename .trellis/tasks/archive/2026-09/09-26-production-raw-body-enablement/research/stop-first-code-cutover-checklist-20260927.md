# Stop-first raw-off code cutover: **blocked, non-executable phase review**

**Scope:** local-only design; not a command file, deploy approval, or live procedure. Do not use this checklist as an instruction to stop the service. No production connection/control or operator-data inspection was performed for this review. The earlier 10-minute approval was **backup-only** and cannot authorize this outage. The separate raw-on, resource, external-backup and older-release acceptance gates remain open. This document intentionally contains no runnable stop/switch/restore helper.

## Decision: do not automate the switch yet

The existing `backup_pause_window.py` and its supervised watchdog can only unpause the **same** container; neither supervises a stopped container nor knows whether a replacement has written multi-key v2 state. The isolated full-copy Compose cycle in `full-copy-code-switch-rehearsal-20260927.md` demonstrated the order on a private copy, not recovery after coordinator/SSH death. A startup may rewrite config/metadata before a coordinator records a successful `up`; a timed-out Compose call is **not** a proof that v2 has not been mounted. Conversely, a watchdog that always restarts the old image can drop account owners and route a Legacy request to a foreign account. A watchdog that always restores v1 may erase unknown operator/diagnostic writes, even if a separate v2 copy exists. A config hash alone cannot fence the whole tree. This particular stop-first proposal has no demonstrated recovery mechanism that preserves availability before v2 while fencing data after an ambiguous v2 write. The deployment spec requires a tested safe rollback/no-op boundary, **not a specific permanent supervisor architecture**; an independently supervised owner is additionally needed if promising automatic recovery after coordinator loss within a fixed outage window. **No executable cutover or automatic recovery is supplied here.** Treat ambiguous states as hold-ingress-closed and escalate to a separately authorized fenced recovery; do not let an outage timer force old-on-v2.

Frozen *historical rehearsal identifiers* for review, **not current preflight values**: committed-main source `4d4ee8798f20a03e842d5cd52f21188bd1f0f88a`, exact built candidate `sha256:bd49772e0a42a2f4f90bc35ce32408485d411caca46efe40c4b13c959105669d`, previous image `sha256:0bd1deaefb04b6c2c3f1e3417eddc07b3fc6dd6398212ff98e6a783c3c62100c`. Recheck *full* IDs, archive hash, source and both images before any later review; prior snapshot-specific config prediction `e56819de…` and Compose/config hashes cannot stand in for a fresh write-fenced snapshot. The release-parent directory is UID-1000-owned: reverify file provenance/image contents, not only its path or tag. The old image supports raw profiles; this raw-off plan requires the raw child to remain empty and isolated, not an assumed validator denial.

## Candidate phases and evidence required before a separately approved implementation

These are design gates, not steps currently authorized to run. Evidence must remain root-private; print only bounded statuses, opaque digests and safe changed-field paths, never config, credentials, file names of private logs, bodies or sidecar contents. Reject symlinks/hardlinks/special entries in the non-raw tree; bound count/bytes/depth and ensure every stage ancestor is root-owned and not group/other-writable. `verification/` and the versioned `releases/` parent do **not** qualify as root-private rollback locations merely because a child is mode 0700.

| Phase | Required observation / hard stop |
|---|---|
| 0 — source and no-op preflight (old still running) | Obtain **separate cutover/outage approval** and a verified plan for ingress/in-flight drain and the *all-writers* fence over DATA_DIR, Compose, env, gateway and deployment sidecars. Activate it before the old-service stop and keep it through the v1 seal and v2 migration gates. Do not invent a fence from `docker stop`, an FD sample, a read-only hash, or an operator promise alone; define who controls host/external writers, how it is maintained across coordinator loss, and how it is tested. Freeze the old exact container ID/image/Compose service, healthy/restart=0/OOM=false, 512 MiB, raw=false, absent ready flag; record current Compose/config/metadata/admin and sidecar hashes, and non-raw inventory. Confirm `main == origin/main`, allowlisted committed archive SHA, release-tree modes/source hashes, exact Compose-built image ID and UID-1000 readable built content. Stage a candidate Compose changing **only** service image and build context; diff resolved services/mount/env/network/memory/flag, and verify that its project + `up -d --no-build` resolve to that prebuilt ID. Predict migration on a *fresh private current copy* (ordered stable account IDs and all non-owner fields, `clientKeys` inventory, all `clientKeyId=legacy`, raw=false); quota metadata may drift, so do not pin a stale metadata hash. Exercise atomic install/restore **only on private scratch**. Check all gates again immediately before the stop; any failure here must leave the same healthy old container, live data and Compose untouched. Private untrusted staging is not a live rollback. |
| 1 — **first live-mutation boundary** | A durable phase record and **tested recovery path** must exist before stopping the exact old ID. If promising bounded recovery despite SSH/coordinator loss, that path additionally needs independent supervision; otherwise disclose the unbounded manual-recovery risk and obtain separate explicit acceptance. Stop only that service; bound wait and verify exact container stopped, no automatic restart/replacement writer, unchanged old Compose and full v1 tree. From this moment a failure is *not* a pre-mutation no-op. No new image, data restore, or `up` while this is ambiguous. |
| 2 — fresh, sealed v1 (old stopped) | Under the uninterrupted writer fence, copy the **entire current non-raw** DATA_DIR to a *new* root-private stage plus authoritative old Compose, actual env_file, resolved gateway target and deployment record. Use a literal anchored raw exclusion (`/detailed-logs/raw/***`); reject nonempty raw for this raw-off switch, and neither traverse nor copy raw groups. Verify framed relative path, each file length/hash, uid/gid/mode, counts/bytes and source → copy → source → final source parity, config/metadata/admin hashes and sidecars. A pre-copy made while old ran, even if config still matches, is not this seal. Restore v1 to a **different private path**, verify full parity and exact old-image startup/health on that copy, never on v2. On backup or restore failure, old can be restarted *only* after proving no Compose/v2 mutation, exact old ID and unchanged compatible v1 tree; if not provable, keep ingress fenced and request recovery decision. Remain stopped between seal and switch. |
| 3 — candidate installation / possible v2 write | Record **two** boundaries: candidate Compose installation (old data can still be v1) and the potentially-v2 candidate `up` call (an ambiguous return may already have started and written v2). Before `up`, exact old image/data compatibility and lack of a candidate writer may permit restoring the old Compose and restarting old after a fresh full-tree check; after an ambiguous `up`, assume v2 until independent evidence proves otherwise. Recheck the v1 seal and current-source digest/fence. Atomically install the prebuilt Compose (same directory, fsync replacement and parent), then `up -d --no-build` using the reviewed project. Never build, prune, change ready/memory, edit live config, or start old on an unknown/v2 tree. An independent supervisor must treat any crash from this boundary onward as **possibly v2**, including a failed/timed-out `up`; a phase marker alone is not evidence of exact data bytes. |
| 4 — immediate new-image gates (no acceptance by health alone) | Require exact new container/image and source, running/healthy, restart=0/OOM=false, 512 MiB, raw=false/no ready flag; compare current config to the **fresh snapshot-specific** migration and only allowed safe paths, all ordered stable IDs/other account fields preserved, every owner Legacy, no extra key and independent admin state unchanged. Inspect metadata changes as safe field paths, not a guessed startup hash; check full-tree unexpected drift. With old ingress still fenced, verify local migration/image/health first; then deliberately open **bounded validation traffic** through public HTTPS/gateway and the internal alias/model path. New logs/metadata written after opening belong to v2 and must be preserved separately before any rollback. Require **positive independent administrator** Cookie/CSRF management reads and client-key-only denial; a protected 401 is negative evidence only. If machine gates pass but operator-only protected pages remain unconfirmed, report **deployed, awaiting administrator acceptance**, not an automatic rollback. Gate migration/traffic separately from the older pending release record. If any hard gate fails, fence all writers before considering rollback; do not silently mark `completed`. |
| 5 — post-v2 fault decision (not automatic) | Fence ingress, drain/stop the **exact new** process, prohibit other writers, then preserve a **complete separate root-private v2** DATA_DIR and matching sidecars before *any* v1 replacement; compare source → copy → source, verify v1 seal and exact old image still exist. Abort restore on any unknown concurrent write, mismatched inventory, unsealed v2, failed private copy, nonempty raw or untrusted sidecar. Even when sealed, determine whether v2 contains intentional operator or traffic writes and obtain a loss/retention decision. Restore complete compatible v1 into a *new* private path and verify its inventory/sidecars before considering an active path change. The live DATA_DIR path/mount replacement, same-filesystem rename and crash windows between renames need their own tested, write-fenced transaction; an `rsync --delete` into the active tree or config-only replacement is unacceptable. Start exact old image only once the **active** full tree/Compose are proved v1, old management/raw ingress is isolated on every reachable path, and model access can be preserved; retain v2 untouched. If old start/health fails, keep both images/data versions private and ingress closed, escalate rather than retrying an old-on-v2 start. |

## Recovery ownership / failure matrix

| Interruption / injected failure | Safe default (not necessarily service availability) | Proof missing before an executable helper |
|---|---|---|
| Before stop, including stage copy/metadata/provenance/hash drift | No stop, no Compose/data change; prove same old ID/health/current tree. Leave partial private stage untrusted. | Persistent, independently checked old-container identity and complete no-op audit. |
| Stop command times out or coordinator dies immediately afterward | **Unknown stop outcome.** Supervisor may restart the exact old ID *only if* it independently proves original Compose **and complete active v1** unchanged, no candidate up/mount, plus external writer/ingress fence still holds. Otherwise hold, page. | A separately supervised, restart-tested stop/start recovery owner, exact-ID and full-tree checks after ambiguous Docker calls, an outage bound that never overrides v2 safety. The pause/unpause watchdog is not it. |
| Copy/verify/isolated-restore failure with old demonstrably stopped on v1 | Preserve failed stage, prove old Compose/whole live v1 unchanged and restart only that old ID; verify health/local route before lifting ingress fence. | Sustained external fence and bounded independent restart/health supervision after coordinator loss. |
| Compose installation, `up`, startup or validation failure (including timeout/lost coordinator) | Assume v2 may have written, **never auto-start old**. Preserve live tree and private v1 seal; hold ingress until an independent full-v2 seal and drift/loss decision permits compatible restore. | Atomic install crash tests, unknown-write detection, full-v2 seal/restore-to-new-path, old-image path/mount switch, independent admin and old-management ingress tests. |
| v2 backup failure, full-tree/sidecar drift, raw group found, or later operator write | Do not overwrite or label as migration; retain current bytes and old/v1 private artifacts, keep affected ingress closed, escalate for fenced recovery. | Positive no-concurrent-write proof and explicit operator decision for any post-switch data loss/reconciliation. |
| Coordinator dies during active-path v1 replacement | No old boot until active path has a completely verified compatible v1 seal; no assumption that two renames are atomic as a pair. | Durable phase transitions plus independent mid-restore crash/replay tests and tested path/mount switch on isolated full copies. |

## Go / no-go for a later reviewed code window

| Gate | Go only if | Otherwise |
|---|---|---|
| Fresh upgrade state | Full current non-raw v1 and authoritative sidecars can be sealed/restored while writes stay fenced through the candidate start; current config migration predicted on an exact copied image | Leave old healthy; do not reuse the earlier resumed-service snapshot |
| Source and runtime | Committed `main == origin/main`, release-tree hashes/modes and exact Compose-built image ID rechecked, raw off/512 MiB/no ready flag | No Compose mutation |
| Stop and rollback | Pre-stop no-op and post-stop v1 recovery tested; ambiguous `up` never boots old on v2; a full separate v2 preservation/compatible-v1 restoration path is tested | Do not promise automatic or bounded recovery; hold ingress and seek a recovery decision |
| Authentication and ingress | Exact `32a150e` rollback raw-child isolation, public/internal/loopback negative checks and positive admin strategy reviewed; new-image local/public/internal and admin checks prepared | Do not equate 401 with acceptance or generalize older `274755…` raw denial |
| Time and ownership | A separately approved maximum interruption and named operator for post-v2 ambiguous recovery, with truthful statement of any coordinator-loss risk | No live switch under the previous backup-only authorization |

A safe independent supervisor could *fail closed* at every ambiguous v2 boundary, but cannot both recover old-service availability within a promised window and guarantee v2/operator data preservation without the missing fences and explicit decisions. Therefore this phase review is deliberately **non-executable**. Do not adapt the backup-only watchdog to restart `32a150e` based on a timer or config hash. Before reconsidering automation, prove the external ingress/writer fence and recovery owner remain active after SSH/process failure; inject loss at each boundary (pre-stop, stop timeout, mid-copy, seal, atomic Compose install, `up` timeout, post-v2 write, v2 copy, and between active-path renames) on a **fresh synthetic/private disposable** full tree. Assert raw exclusion, v1/v2 sidecar and inventory parity, no old-on-v2, no unintended live overwrite and bounded recovery; retain original/versions on failure. Then obtain independent review and a new exact cutover authorization. No production helper execution, release switch or raw-on acceptance follows from these offline tests.
