# Bounded isolated raw stress with pre-load read-admission proof — 2026-09-26

**Only synthetic data and Docker-internal traffic.** This follow-up improves the earlier unsynchronized overlap check in `target-load-20260926.md`, but it does **not** prove that server-side read slots remained occupied throughout the large-chat burst. Its results must not be folded into the earlier run. Exact committed-`main` source `4d4ee87` produced Compose-built image `sha256:f7c45edc2ccba0eab83baea36db65ffe70e4a19fd4c1b275b8fa6565f4e765bd`. The 2 GiB service used UID/GID 1000:1000, read-only root, dropped caps, no-new-privileges, tmpfs and an internal network without host ports. It used a fresh synthetic config/admin copy and a synthetic Node mock upstream; production DATA_DIR, model credentials and public ingress were not used.

## Deterministic checks

- With `rawBodyLogging=false`, one 34 MiB request (`35,651,664` UTF-8 bytes) returned 200 and a `35,651,731`-byte response. The mock embeds the received request byte count in its response. After isolated administrator Cookie+CSRF persisted raw=true and read it back, an identical seed request returned **the same status, byte length and SHA-256** with the expected mock-observed request byte count.
- Four independent authenticated `GET .../bodies/<bodyId>` HTTP/1.1 sockets reached status 200 and were paused after receiving response Headers and possibly a small initial body chunk. **Before starting the chats**, a fifth authenticated body read returned **503**, consistent with the four-read admission limit. Four client sockets remained open during the next workload, but the harness did not re-probe the limit during/end-of-load; continued server-side slot occupation is **unproven**. The sockets were then destroyed; no body text, cookie or token was printed.
- While those four **client sockets remained open**, three identical 34 MiB chats and an SSE first-data/cancel were client-initiated via `Promise.all`. All three chats returned **200**, with downstream response byte length/SHA-256 matching the raw-off baseline. The synthetic mock echoed the received request byte **count**, not a request-body digest; upstream input bytes and lease/retry equivalence were not proved. One SSE request observed a first `data:` event and was cancelled. A separate bounded ordinary-log inspection (not a client-harness assertion) counted **5 success / 1 client_cancelled** (baseline + seed + three stress chats + SSE); five `raw-full` directories existed. These facts support bounded downstream parity, not paid-model or sustained-load parity.
- `health.dropped=2`, exclusively `captureBudget=2`; raw manifests had 13 `complete`, five `resource-limited` and two `interrupted` body descriptors. Raw group presence **does not** mean every body was captured. A bounded scan found no synthetic upstream key or repeated synthetic body marker in ordinary request JSONL or raw manifests; this is not a universal credential-leak proof. The deliberate budget fence was left unchanged.
- Service cgroup `memory.max=2,147,483,648` bytes, `memory.peak=1,467,203,584` bytes (~680 MB observed margin), `memory.events.oom_kill=0`; running container had zero restarts/OOM false. An isolated telemetry preload (not part of the image source; 250 ms sampling, 20 ms loop histogram) recorded max process RSS **1,236,766,720** bytes, max heapUsed **509,757,616** bytes, max external **431,673,539** bytes, cumulative-from-start event-loop delay histogram p99 **29.52 ms**, histogram max **836.76 ms**. CPU was not measured; sampled RSS can miss shorter peaks. The high max delay and diagnostic losses require explicit acceptance/headroom review, **not** automatic selection of 2 GiB as a safe live limit.

After the stress run, isolated raw was persistently set false and authenticated readback confirmed it before stopping service/mock containers. The production container remained on the old exact image, healthy with zero restarts/OOM false and 512 MiB; live Compose/config/deployment hashes matched preflight, live raw-ready flag absent. Source/image/synthetic groups and the internal test network are retained pending later gates/cleanup consent; no production service switch, raw capture or data copy occurred.

## Open gates

- This tests one bounded burst, one mock response shape and four paused client download sockets; only a pre-load fifth-read 503 confirms server admission at that instant. It does not establish sustained throughput, all 35 MiB boundary cases, long-running RSS/CPU, 48h recovery, production NewAPI behavior or final memory headroom. `captureBudget` omissions and the 836.76 ms observed maximum loop delay need a reviewed acceptance criterion or mitigation without weakening safety fences.
- Actual backup copier raw exclusion or independent private 48h expiry, complete pre-upgrade v1→v2 migration/hash prediction and rollback, old-image management ingress isolation, the exact final candidate Compose/flag, and administrator-only browser/transport verification against the isolated real service remain incomplete. Production enablement is **blocked**. The September 24 release's mismatched config acceptance remains separate.
