# Current profile and Header boundary (planning, 2026-09-26)

- `server.js:4683-4691` snapshots one profile at request start. When both `detailedLogging` and `errorDetailLogging` are true, full wins; with `rawBodyLogging:true` it becomes `raw-full`, not two groups. `server.js:4813-4823` strictly accepts a nonempty subset of the three boolean settings, rejects raw=true without runtime availability, and persists before mutating runtime. `config.rawBodyLogging` defaults false (`server.js:59,1180`). The operator confirmed retaining this independent opt-in and runtime readiness/memory gate.
- `lib/detailed-log-capture.js:431-564` builds `raw-full`/`raw-error` bodies. Raw full records ingress/attempt/downstream bodies; raw error holds failed-attempt request/response bodies and releases successful-attempt copies, including after eventual request success. The raw branch currently emits no Header maps; sanitized full records request/response and attempt Header maps via `DetailRedactor.headers()`, while sanitized error records only failed-attempt response Headers.
- `lib/detailed-log-store.js:97-135` excludes Headers from raw manifest allowlists, so adding a Header projection to capture alone would make publication fail. The list `summary()` stays metadata-only. A revised raw detail projection needs independent bounded safe Header name/value construction and validation, with no value sourced from the 35 MiB raw body. Credentials, URLs and arbitrary account/provider text stay absent; explicit raw *body* content remains the only unredacted exception. Existing sanitized legacy groups/validators and old-image denial must be preserved.
- `lib/detailed-log-capture.js:206-215` has a legacy group-aware sanitizer that discovers secrets across Header/body values. It cannot simply be invoked on raw content without changing raw-body semantics or materializing large bodies, and a generic `text()` pass over arbitrary Header values is not a complete credential guarantee. Prefer a small bounded allowlist of independently safe Header values (e.g. strictly parsed known numeric/media facts) and redact/omit unknown values; reject dangerous Header names/values and unsafe manifest shape at the store boundary. Exact allowlist and rendering/API schema remain design work, not validated behavior.
- `lib/detailed-log-store.js:104-135` validates raw profile metadata with strict key sets, group timestamp and body references. `test/raw-detail.test.js`, `test/detailed-log-capture.test.js`, `test/integration.test.js`, `test/detailed-log-ui.test.js`, `test/admin-auth.test.js`, and `test/ui-contract.test.js` cover the affected owners; tests must cover both switch precedence and all request/response/attempt Header projections without putting credentials into lists, ordinary JSONL or metadata.
- This read-only inspection does not prove production resource or browser safety. Production still runs `32a150e` with raw disabled under 512 MiB according to the task's prior safe projection. No production access or setting write was made for this note.
