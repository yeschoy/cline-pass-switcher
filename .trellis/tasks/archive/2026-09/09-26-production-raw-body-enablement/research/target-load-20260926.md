## Load results actually observed

1. Two concurrent nonstream synthetic requests with 34 MiB input each and ~34 MiB mock responses each returned HTTP 200, identical 35,651,710-byte response sizes and two `raw-full` detail groups. A paused authenticated body read and SSE first-data/cancel were exercised. One `captureBudget` diagnostic omission was reported; chat remained usable.
2. On a fresh synthetic config/admin copy, the same pair of concurrent 34 MiB chats returned 200. **After that pair settled**, the harness attempted to overlap one more 34 MiB chat, a paused authenticated body read and SSE first-event cancellation. The third chat returned 200 with the same 35,651,710-byte response. This version had no synchronization proof that the server still held the slow read when the chat ran, so it does **not** establish three simultaneous large chats or a held server-side read. Ordinary rows were **3 success / 1 client_cancelled** and four owned raw directories existed. `health.dropped=1`, exclusively `captureBudget=1`; this is a bounded diagnostic drop, not a request failure. No paid upstream or host port was used.
3. The second run's service cgroup peak was **1,015,857,152 bytes** under the **2,147,483,648-byte** limit; `memory.events` showed zero `oom`/`oom_kill`, container remained running with zero restarts/OOM false. An isolated `NODE_OPTIONS=--require` telemetry preload (not in the released image) sampled max process RSS **853,692,416 bytes**, max heapUsed **330,614,896 bytes**, max external **391,081,211 bytes**, event-loop delay p99 **24.46 ms**, max **149.42 ms** at 20 ms resolution. The preload adds measurement overhead and is not a claim of an uninstrumented production bound. This observed workload left ~1.13 GB cgroup margin, not a proof for arbitrary concurrency, held downloads, larger response patterns or long-duration traffic. The delay histogram is cumulative from startup, RSS/heap are 250 ms samples, and CPU was not measured.
4. After both runs, the isolated raw setting was persistently disabled and read back false **before** stopping the synthetic service. Service and mock containers were stopped; the private synthetic fixture/source/image were retained, not pruned. Post-check production Compose/config/deployment hashes matched the preflight, and the live container remained on the original image, **512 MiB**, running/healthy with zero restarts/OOM false. Production raw was never enabled and no production body was read.
