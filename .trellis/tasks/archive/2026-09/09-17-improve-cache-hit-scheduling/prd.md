# 调研并优化缓存命中率调度与并发策略

## Goal

基于 cline-pass 当前账号池、请求流量与真实缓存统计，提高缓存请求命中率，同时保持缓存 Token 收益、可用性、延迟和账号额度安全。

## Background

- cline-pass-switcher 分别统计缓存请求命中率与缓存 Token 占比；缺失 usage/cache 字段不会被推断为 0。
- 2026-09-16 只读生产基线显示：9 个配置账号中 7 个启用，当前 6 个 hot、1 个 warm；模式为 sticky，流水线为健康过滤 → 额度池 → 健康排序 → 粘性，启用账号均未设置并发上限。
- 最近 24 小时缓存请求命中率为 `1269/2176 = 58.32%`，缓存 Token 占比为 `153143234/182635883 = 83.85%`；明确 usage 的请求全部带明确 cache 字段。
- 最近 24 小时 2,394 条普通请求没有容量溢出、容量回退、首选/实际账号不一致或换号；估算全局峰值并发为 7，单账号最高为 5。因此当前并发调度不是已证实的缓存损失来源。
- 最近 24 小时全部请求的会话来源均为 `message_hmac`，没有 `prompt_cache_key`、Session/Thread Header 或 body session 字段；当前粘性依赖开场消息稳定性。
- 生产 NewAPI 渠道 71 不生成、同步或透传显式会话键；`/v1/messages` 转换为 `/v1/chat/completions` 时不保留原始 `metadata`。NewAPI 只作为只读证据边界，不属于本任务的修改范围。
- 当前普通日志不保留会话指纹，无法量化新会话正常冷启动、会话内账号/provider 迁移或同会话并发重叠分别造成多少未命中。
- cline-pass 账号池的直接调度所有者是 switcher；CPA 不参与本任务。

## Requirements

1. 保留只读、脱敏的生产基线与根因分级，明确区分已确认事实、高概率因素和不可观测项；不得读取或输出凭据、代理地址、Header 值、原始会话或消息正文。
2. 以缓存请求命中率为主要指标；缓存 Token 占比、usage/cache 字段覆盖率、最终失败率、P95 延迟、备用账号溢出率和额度/健康状态作为护栏。
3. 新会话默认仅在 2 个活跃账号中进行粘性分配，其余符合基本资格的账号作为备用，以缓存集中度换取更高请求命中率。
4. 活跃池复用现有账号 `priority` 稳定选定。普通额度百分比或健康分数波动不得频繁重排；只有账号禁用、封禁、冷却、明确不健康或额度进入 reserve（≥95%）时，才由下一优先级可用账号替换。优先级并列时选择必须稳定且可测试。
5. 同一可识别会话在活跃池不变时必须继续命中同一账号；没有显式会话键时继续使用现有消息 HMAC，不记录其原始值或指纹。
6. 两个活跃账号因并发上限全部满载时，先等待 5 秒，再允许溢出到备用账号以保持可用性；溢出必须进入现有安全诊断，不得静默发生。当前账号不限并发的兼容行为不得降低吞吐。
7. 旧配置和旧客户端保持兼容：未启用缓存活跃池时，现有六种账号模式、四步流水线、账号选择序列及容量行为不变。
8. 管理 API、持久化配置、控制台草稿/原始配置编辑器和普通日志对新增策略使用同一契约；严格校验必须在写文件或改变调度状态前完成。
9. 提供一个可预览、可取消的“缓存命中优先”配置入口，但不得修改账号名称、Key、启用状态、代理、Header 或模型路由；普通显式保存仍是持久化边界。
10. 在用户审阅最终规划后，实现 Switcher 侧最小代码/配置支持与自动化测试。生产配置调整和部署必须另行明确批准。

## Acceptance Criteria

- [x] 研究报告覆盖当前账号池、缓存口径、命中率、请求分布、并发特征、NewAPI 会话字段边界及证据限制。
- [x] 默认关闭的新策略对旧配置、旧客户端和现有六种账号模式保持行为兼容。
- [x] 启用策略后，仅优先级最高的 2 个合格账号承载正常新会话；同一会话稳定命中同一账号，备用账号不会在正常容量下接收请求。
- [x] 普通 hot/warm 百分比和非“不健康”分数波动不改变活跃池；禁用、封禁、冷却、明确不健康或 reserve 账号退出活跃池，并由下一优先级账号确定性补位。
- [x] 两个活跃账号都满载时等待 5 秒；等待后可用容量优先回到活跃池，否则使用备用账号并记录明确的备用溢出诊断；无任何可用账号时仍返回现有安全 429/503 语义。
- [x] 新配置字段经过启动迁移、严格 API 校验、原子持久化和保存/重启 round trip；非法、未知或越界值返回 400 且不改变原文件。
- [x] 控制台完整保存、筛选、抽屉、批量并发、预设和原始调度编辑不会丢失账号隐藏字段或新增策略草稿；预览取消不产生请求或状态修改。
- [x] 普通诊断只增加安全枚举/数值，不包含原始会话、HMAC 指纹、账号 Key、代理、Header 值或正文。
- [x] 聚焦测试、`node --check`、生产脚本 VM/UI 契约测试、`npm test` 与 `git diff --check` 全部通过。
- [x] 后续生产试运行标准已定义：预热后观察满 24 小时且至少 1,000 个明确缓存样本，缓存请求命中率达到 70% 以上；缓存 Token 占比较 83.85% 基线下降不超过 3 个百分点，最终失败率上升不超过 1 个百分点，P95 延迟恶化不超过 20%，备用账号溢出率低于 1%，且活跃账号不进入 reserve 或持续不健康。本任务在未获部署批准时不得声称已达到该生产指标。

## Out of Scope

- 修改 NewAPI 或 CPA 的代码、配置、部署与运行状态。
- 本轮直接修改生产配置、账号池、容器或部署版本。
- 读取或记录原始会话、消息正文、凭据或其他敏感请求内容。
- 在生产试运行前承诺一定达到 70% 命中率。
