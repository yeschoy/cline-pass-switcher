# Price extension design — current ClinePass + DeepSeek reference

## Owners and source versions

Keep `REFERENCE_PRICE`, `referenceValue()`, v5 valuation minute cells and the additive `referencePrices` statistics API in `server.js` as sole owners. Existing `clinepass-2026-09-24-v1` rates/shape are immutable historical facts. New v2 internal snapshot has all **12 current ClinePass model IDs** and source/collection metadata. Direct DeepSeek's rate rows for `cline-pass/deepseek-v4-pro` and `cline-pass/deepseek-v4.1-flash` carry an explicit *per-model source* `https://api-docs.deepseek.com/quick_start/pricing/`; all others cite current `https://docs.cline.bot/getting-started/clinepass`. The DeepSeek `cline-pass/*` ↔ direct API name association is based on the explicit current ClinePass model list and direct DeepSeek version; do not infer that legacy `cline-pass/deepseek-v4-flash` aliases V4.1. DeepSeek Pro has same peak/off-peak values in both sources, while ClinePass shows only V4.1 Flash peak and the DeepSeek source supplies its off-peak row. Neither source provides an official model-specific effective date. Request-time valuation uses the then-current internal version; later price changes add versions rather than rewriting stored cells.

## Exact fixed-point schema and calculation

Historical v1 snapshot validator keeps exact six top-level keys, `rates` triples in integer **thousandths** USD/1M, and its existing source/tiers; do not run a v2 validator over persisted v1. Define a strictly validated v2 shape with `rateScale: 10000` (ten-thousandths USD/1M) and per-model `{tier, rates, source}`; each rate row has four bounded fields `[input, output, cachedRead, cachedWrite|null]`. `null` for Cached Write means the reference table shows `—`, not that a measured cache-write count is zero. Tier is `single`, `peak/off-peak range` or `context-band`; the two DeepSeek rows have explicit lower/upper rate triples (off-peak/peak) but return only a **range**, since even a UTC weekday does not prove Chinese holiday status or ClinePass's actual applicable tier. A Qwen `context-band` or any priced Cached Write row is a tariff fact, not enough to calculate full amount from existing usage.

Use existing `normalizeUsage()` explicit input/output/cached-read values and `cachedRead <= input`. For a no-write price row with supported tier, each amount in picodollars is `BigInt(input-cachedRead)*rateInput*100 + BigInt(output)*rateOutput*100 + BigInt(cachedRead)*rateCachedRead*100` at v2 scale 10000 (USD/1M); v1's old x1000 multiplier remains unchanged. `0.0028`, `0.0145`, `$3.125` and DeepSeek `$0.003` are exactly representable without floating-rate rounding. Continue safe integer overflow -> null/coverage, unknown input/output/cache -> no valuation, and no backfill. The named Provider bucket receives the one final successful usage only when attribution is proved; unknown Provider bucket remains explicit. Do not change account quota arithmetic or route/lease/retry semantics.

## API and browser handoff

Extend `GET /api/statistics.referencePrices` additively so the UI can list v2 rates/source/tier even when `valuation` is unavailable; retain v1 versioned valuation display without confusing units. Keep amounts labelled `参考消费等值（USD），非订阅实际扣费`, with eligible priced-request count versus final successful samples and missing/partial coverage. The later model/Provider UI simplification child owns compact tabs and row disclosure, but this child must ensure a minimally correct existing page can consume the additive v2 snapshot and show model tariffs, DeepSeek interval, unpriced reasons, source/version and unknown official effective date. Browser-controlled strings are escaped/textContent, no new client store or build tool. Account monthly-reference forecast remains the existing separate `$50 × remaining monthly percent` projection and tests; model consumption never reduces it.

## Compatibility and rollback

The strict historical snapshot validator, 8 price-version and 16 model limits and v1–v5 statistics migration must continue to accept previous metadata without rewriting original bad bytes. A current v2 snapshot may be persisted alongside referenced v1 cells; `validateStatistics()` rejects malformed/foreign/special-object keys and never reprices old cells on boot. Price/source/schema changes need backend + frontend specs and operator docs/examples where user-visible, focused temporary-DATA_DIR tests, browser production script VM checks and full project gate. Rollback must be tested on a private *synthetic copy* because an older binary may not understand new persisted v2 snapshots; do not deploy without a separate rollout/rollback authorization.
