# 修复额度解析并支持可排序调度流水线

## Goal

恢复 Cline 账号 5 小时、周、月额度的可信展示与路由分层，并允许操作者将四个可选账号调度步骤任意拖动排序。

## Background

- 线上 `GET /users/me/plan/usage-limits` 当前返回 HTTP 200、`success: true` 和三个有效额度窗口，但 `resetsAt` 使用 9 位小数秒，例如 `2026-09-16T01:41:26.552188975Z`。`server.js:311-333` 只接受 1–3 位，因此整次快照被归类为 `schema`，页面显示“刷新失败（数据格式）”。
- 当前 `accountPipeline` 只有 `quotaPool`、`excludeUnhealthy`、`healthSort`、`sticky` 四个布尔开关；执行顺序在 `server.js:587-650` 固定，UI 也明确展示为固定顺序。
- 原流水线需求曾明确禁止任意拖拽；本任务由用户的新要求取代这一产品限制，但仍须保留硬资格过滤、租约、容量、最多一次换号和敏感数据边界。

## Requirements

### R1 — 额度时间兼容

- 接受 Cline 当前返回的 RFC3339 1–9 位小数秒重置时间，并在持久化/API 输出前规范化为既有毫秒 ISO 格式。
- 5 小时、周、月额度及其重置时间必须一起恢复；非法时间、非法比例、重复窗口等既有拒绝规则不得弱化。

### R2 — 四步骤任意排序

- `excludeUnhealthy`、`quotaPool`、`healthSort`、`sticky` 四个可选步骤均可在控制台拖动到任意位置，并可独立启停。
- 排序必须成为持久化配置和实际后端执行契约，而不只是 UI 顺序。
- 顺序越靠前优先级越高，后续步骤只在前一步形成的同级候选组内继续细分；sticky 位于前部时优先于后续额度/健康分层。
- 硬资格过滤继续固定在流水线之外最先执行；现有账号模式继续负责最终租约与容量行为。

### R3 — 兼容与安全

- 旧配置缺少顺序时迁移为当前固定顺序，升级后行为不变；四项全关继续走 legacy 快路径。
- 旧管理客户端未提交新顺序字段时不得静默重排已经保存的流水线。
- 配置严格校验；未知、重复、缺失或非法步骤不得产生部分保存。
- 不改变账号 Key、代理、会话指纹、额度原始响应和日志的敏感数据边界。

### R4 — 生产部署

- 仅部署已提交 `HEAD` 的白名单发布包，私钥、工作区改动和本地配置不得进入发布物。
- 在生产数据副本上预演配置迁移；只有精确新增默认 `accountPipeline.order` 时才接受预测后的配置哈希。
- 切换前保留 compose、deployment、配置和 metadata 备份；健康、认证 API、内部网络、配置哈希或非预期迁移失败时恢复配置并回滚。

## Child Task Map

- `09-16-quota-reset-time-precision`：额度时间兼容及回归验证。
- `09-16-sortable-account-pipeline`：排序配置、执行语义、拖拽 UI、迁移与跨层验证。

## Cross-Child Acceptance Criteria

- [x] AC1：真实线上格式的三个额度窗口可解析、规范化、持久化并在统计页显示；错误输入仍安全失败。
- [x] AC2：四个步骤可任意重排、启停、保存和重启恢复，后端按保存顺序执行。
- [x] AC3：旧配置、旧客户端和四项全关的六种账号模式兼容行为保持不变。
- [x] AC4：拖拽支持键盘等价操作和明确状态反馈，原始调度编辑器与普通控件共享同一草稿。
- [x] AC5：额度刷新、聊天关键路径、租约释放、容量回退、最多一次账号替换及敏感数据测试通过。
- [x] AC6：两个子任务独立通过检查后，父任务执行一次跨子任务集成复核。
- [x] AC7：版本化远程部署通过镜像、健康、API、内部别名和预测配置哈希门禁，并保留完整回滚材料。

## Out of Scope

- 修改额度池 80%/95% 阈值、刷新频率、并发数或失败退避。
- 修改健康评分公式、错误规则或供应商重试协议。
- 将固定硬资格过滤变为可拖动步骤。
