# Current error/detail contract (read-only, 2026-09-27)

## Evidence

- `server.js:2912–2940` projects one bounded ordinary error row per failed native attempt: sanitized `reason` <=16 KiB, attempt index, optional detail profile/call ID. It does not persist a body or arbitrary Header value. `.trellis/spec/backend/logging-guidelines.md` prohibits either in ordinary JSONL.
- `public/index.html:1648–1663,1685–1700` has an existing validated detail button that switches section; it checks request UUID + attempt index + call UUID and filters the detail group to the matched attempt. `test/detailed-log-ui.test.js:148–180` checks mismatch denial and legacy missing intent. The requested **same-section four-leg view** is different from this existing navigation.
- `server.js:4684–4694` chooses `raw-full` when `detailedLogging && rawBodyLogging` are accepted, `raw-error` when only error detail + raw are accepted; raw availability needs initialized admin, explicit runtime readiness and >=2 GiB limit per `.trellis/spec/backend/logging-guidelines.md:339–345`. The separate production raw-enablement task states live raw remains off; this planning task does not flip it.
- `lib/detailed-log-capture.js:440–580`: raw-full records ingress request Header/Body, each native attempt request/response Header/Body, final downstream response Header/Body. Raw-error records only failed attempt request/response; it has no ingress/downstream pair. A failed attempt followed by a successful final client response still exists in raw-full as distinct legs. Missing response, incomplete stream, diagnostic resource drop, expired/cleared group and >35 MiB/invalid-UTF8 body are not reconstructible by UI.
- `lib/raw-detail-headers.js` permits eight bounded names only; Authorization/Cookie/Set-Cookie values are fixed `[REDACTED]`, custom Header values omitted and only tightly validated structural values displayed. The user's requested Headers can be shown **only as this safe projection**, not verbatim credentials. Raw bodies remain unredacted and can include private messages/keys. `test/integration.test.js:4375–4440` verifies both profiles and ordinary/log exclusions.
- Current detail body endpoint is authenticated, text/plain/no-store/nosniff, on-demand and bounded; `public/index.html:1631–1667` clears selected raw text on navigation/selection and uses textarea/textContent for content. Same-section UI must preserve or strengthen those fences, never fetch raw bodies on each `loadLogs()` or serialize them into row `innerHTML`.

## Planning consequence

Reuse the existing raw-full group and body API, not a second store, ordinary schema or broadened raw-error profile. A selected ordinary error row may identify one failed attempt, but the four-leg group has request-level ingress/downstream and possibly multiple attempts. Inline UI must explicitly distinguish these and verify exact attempt identity before allowing body reads. `raw-error` and sanitized profiles must show an honest partial/sanitized result rather than claim four raw legs. Production availability depends on the separate raw cutover gates, not on this UI change.
