# Design: inspect captured four-leg diagnostics in error-log section

## Boundary

- Reuse ordinary `GET /api/logs/errors` for bounded, sanitized rows; **never** add raw bodies/headers to its JSONL schema or list response. Reuse authenticated `GET /api/logs/details/:requestId` for the request group and `GET /api/logs/details/:requestId/bodies/:bodyId` for one selected body. No new capture profile, store, public endpoint or raw toggle. Do not change current production raw-body state; the separate production-enablement task retains that gate.
- A row's `requestId`, `attemptIndex`, `detailCallId` must pass existing UUID/integer validation. After fetching the group, match exactly one attempt by *both* index and call ID; verify returned request ID and detail profile. Never display an adjacent attempt as the selected failure, even if another attempt in that request succeeded. On mismatch or missing group, show an explicit unavailable state without fetching any body.
- `raw-full`: display four individually labelled segments, with request-level inbound headers/body, matched upstream attempt request headers/body, matched upstream attempt response headers/body, and request-level final downstream response headers/body. Label upstream attempts and final outcome independently (a failed attempt may be followed by a successful final client response). Headers are the existing **safe projection**; Authorization/Cookie/Set-Cookie values remain redacted and arbitrary custom headers remain omitted. Bodies can be unredacted only when already collected under `raw-full`, within existing size, UTF-8, capture-budget and retention bounds.
- `raw-error`: show only the matched attempt's two upstream segments and mark inbound/final as not captured; sanitized `error`/`full` profiles show only captured sanitized portions, explicitly not raw. `captureState`, body state/size and missing response must be labelled honestly; historical or dropped details are not reconstructible.

## UI lifecycle

- In `public/index.html` error rows, retain the existing “查看错误详情” navigation, and add one explicit “在此查看链路” button. Clicking it requests group metadata only; body text is fetched only on a second explicit choice of *one* body. One inline viewer at a time, under the current error row, not every row on page load. Reuse `api()`; keep the per-error-log `LOG_QUERY_ID`/selection generation and abort controller scoped to this view. Page navigation, filter/pagination/reload, choosing another row, auth failure, clear, and `pagehide` discard references and clear visible raw text; stale async completions must not resurrect it. Do not keep all loaded bodies in a global cache.
- Render arbitrary group/attempt/diagnostic text via `textContent` or read-only textarea; generated arguments use `jsArg()`, all server-controlled `innerHTML` values use `escapeHtml()`. Put concise metadata, safe projected headers and individually labelled body-state buttons in a controlled panel; show raw-body warning before a body load. Use native buttons, `aria-expanded`/`aria-controls`, an `aria-live` status, focus entry into the panel and return to trigger on close, and horizontal overflow for large safe metadata on narrow screens. Body copy behavior inherits the existing explicit detail viewer and its clipboard-fallback warning.
- Loading a metadata group may include captured structural values but no body bytes; do not automatically call the body endpoint, including on error-list refresh. If group/body is gone between calls, clear text and report unavailability. Keep the existing details section and its independent navigation controller intact.

## Evidence / rollback

- Extend `test/detailed-log-ui.test.js` with matched/mismatched call IDs, four raw-full legs, raw-error partial legs, late fetch after switching/reload, body-on-demand, missing/truncated body state, DOM escaping, focus handling. Extend local-mock integration tests only for needed server response/profile contracts and ordinary JSONL exclusion. Run the frontend VM tests plus real-browser click, keyboard/focus and narrow viewport acceptance. On rollback remove the same-section viewer; existing details navigation and raw capture settings remain unchanged.
