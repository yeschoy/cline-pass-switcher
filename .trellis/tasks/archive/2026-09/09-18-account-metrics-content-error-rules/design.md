# 统计、日志与错误规则体验总设计

## 1. 任务边界

本任务作为父任务保存用户的完整需求、跨子任务约束和最终集成验收，不直接承担业务实现。三个子任务分别拥有独立可验证的交付物：

| 子任务 | 交付边界 |
|---|---|
| `09-19-model-cache-statistics-ui` | 每模型 24h 缓存 Token 占比、账号摘要、上游发现语义、额度展示去重 |
| `09-19-optimize-ordinary-jsonl-logs` | 普通请求/错误 JSONL 的后台恢复、增量写入、保留与查询性能 |
| `09-19-visual-content-error-rules` | 内容匹配规则、兼容 schema、可视化规则表和统一高级 JSON 草稿 |

父任务只在三个子任务完成后执行跨层回归、规格一致性复核和最终收尾。

## 2. 共同约束

- 保持原生 Node.js ESM、单文件静态前端和现有依赖边界。
- 不改变账号选择、provider 重试、首包后 SSE 禁止重放、额度路由或缓存活跃池算法。
- 统计和诊断失败继续 fail-open；管理配置保存仍由服务端严格校验。
- 所有未知值与已知数值 0 分开；所有服务器文本在 HTML 中转义。
- 普通日志与详细日志保持完全独立：本任务不扩大普通日志投影，也不修改详细正文捕获协议。
- 完整账号保存必须保留稳定 ID、`perModel`、代理/Header、备注及全部调度字段。

## 3. 子任务依赖与顺序

推荐执行顺序：

1. `09-19-optimize-ordinary-jsonl-logs`
   - 已有生产冷启动证据，风险最高且与其他功能无 schema 依赖。
2. `09-19-model-cache-statistics-ui`
   - 修改统计持久结构和两个管理投影，完成用户直接可见的模型/账号/额度修正。
3. `09-19-visual-content-error-rules`
   - 修改配置 schema 和聊天失败处置链，最后独立验证流式/换号安全。
4. 父任务集成复核
   - 检查三者合并后的启动、chat finalization、账号草稿、统计刷新、日志 API 和完整测试。

树结构不是依赖系统；上述顺序同时写入各子任务计划，避免并发修改 `server.js`、`public/index.html` 和共享测试造成冲突。

## 4. 兼容与回滚

- 每个子任务单独提交，出现回归可按相反顺序回滚。
- 统计 schema 必须显式迁移旧元数据；错误内容规则使用独立兼容字段，旧状态码规则无需迁移。
- 普通日志继续读取既有 JSONL 文件，不进行格式迁移或破坏性清理。
- 不在本任务中执行生产部署；生产 rollout 需要单独授权和 deployment guideline。

## 5. 最终集成门禁

- 三个子任务各自 focused tests 和完整项目 gate 通过。
- 父任务再次执行 `node --check`、前端脚本编译、完整 `npm test` 和 `git diff --check`。
- 用真实浏览器验证模型表、账号表、额度列及错误规则编辑器的桌面/窄屏、键盘、焦点和草稿行为。
- 确认普通日志恢复期 503 不影响模型流量、统计页面或详细日志页面。
- 确认内容规则、统计新增和日志优化没有扩大任何凭据/正文投影。
