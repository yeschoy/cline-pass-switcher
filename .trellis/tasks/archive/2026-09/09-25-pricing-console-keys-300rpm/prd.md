# 模型价格、简洁统计、多客户端密钥与性能优化

## Goal

在现有 Cline Pass 代理上分四项独立交付：扩大有依据的模型**参考用量等值**覆盖、简化模型/渠道统计页、按客户端 API key 隔离账号调度，以及**审查整个程序的慢操作并按证据提高性能**。300 RPM 只是将来可能使用的一个整机负载验证场景，不是性能工作的中心或唯一验收条件。父任务只统筹需求和跨项验收；不直接实施代码。规划评审前不启动实施。

## Background / confirmed facts

- 用户最初截图与归档 2026-09-24 的 13 模型 ClinePass 官价一致；2026-09-25 官网已改为 12 个模型（差异见价格子任务 `research/price-source-drift-2026-09-25.md`）。用户随后明确要在**模型和渠道页**用最新官价和上游明确用量计算便于统计的消费等值，其中 DeepSeek 价格按 `https://api-docs.deepseek.com/quick_start/pricing/` 的 V4 Pro / V4.1 Flash 高低峰费率；无可靠节假日/档位事实时仅给区间。ClinePass 仍是订阅制，USD/百万 Token 费率是参考消费等值，非真实额外扣费；旧版金额冻结且采集日不是官方生效日。
- `server.js:872-910` 当前只给旧版 Kimi K3、GLM-5.3、DeepSeek V4 Flash/Pro 估值，版本化历史已冻结。`normalizeUsage()`（`server.js:2412-2425`）没有 Cached Write 计数和上下文档位；不能凭新价格为 Qwen 等模型捏造完整金额，亦不能把已退役的 ClinePass `deepseek-v4-flash` 无证据映射到新 V4.1 Flash。账号**推测月剩余额度另有既有规则**：当前前端已按社区参考 `$50 × (100 − 月窗已用百分比)/100` 逐账号计算，见 `public/index.html:1323-1347` 和测试；模型消费等值不得改写这条规则。
- `public/index.html:160-168,1356-1405` 将模型最终请求与渠道真实尝试、最终成功 usage、价格版本和覆盖警告混入一张大表。用户要求拆成“模型”“渠道”子标签并压缩默认展示；建议把模型列叫“请求成功率”、渠道列叫“渠道尝试成功率”，每格仅显示 `百分比 · N 样本`，把“最终请求”等口径说明放在简短帮助中，保留未知/覆盖详情入口。
- `server.js:1935-1942,4588-4599` 目前只接受单个客户端 `PROXY_KEY`；独立管理员会话已交付，客户端 key 不能访问管理路由。`POST /api/security` 和控制台安全区仍管理单 key；`acquireAccountLease()` 当前从全账号池选取（`server.js:1910,4271-4320`）。用户确认**每个上游账号只属于一个客户端 key，不在 key 之间共享**；所有现有账号归属现有 key。
- 用户明确纠正：**核心是对整个程序所有关键流程做性能审查，找出比较慢的操作并提高性能**；300 RPM 仅作为一个后续参考负载，不应把性能审查限制为该速率、某个客户端 key 或某个预想热点。不新增 per-key 限流。现有 `maxRpm` 按上游账号/真实 Provider attempt 限制，`maxConcurrent` 限在途账号 lease；RPM 不等于并发。`pruneStatistics()` 扫最近 24h 桶及 `record()` 同步保存元数据（`server.js:2489-2567,2739-2832`）是需分段归因的候选；规划期隔离实验将合法合成统计从 1 桶/约 16 KB 扩至 1200 桶/13.39 MB，小聊天 p50 从约 2 ms 增至 18–20 ms，统计 GET p50 从约 1.5–1.8 ms 增至 14–23 ms（两次运行，`research/local-latency-results.md`）。这是规模相关的相关性，**尚不能证明是哪一个函数导致**。普通 JSONL 已有有界队列。归档 5 MiB 脱敏样本约 118 ms event-loop p99 不是全程序或目标容器证据。只用隔离本地数据/模拟上游实验，生产需单独授权。

## Requirements and child ownership

1. **模型/渠道参考消费等值** → `09-25-expand-reference-prices`：按当前 ClinePass 12 模型与用户指定 DeepSeek 官网峰谷费率，对明确返回的最终成功 input/output/cached-read Token 计算可可靠估值的部分；展示不能计算模型的参考单价/原因，历史版本不重算，明示非订阅实际扣费。账号月参考剩余继续按 `$50 × 月剩余百分比`，不与模型消费相减。
2. **管理台** → `09-25-simplify-model-provider-console`：两个子标签分别展示最近 24h 模型/渠道，默认表格只保留简洁的成功率、关键用量/缓存与金额；详情按需展开，未知与覆盖不能伪装成零或完整。渠道维度保留模型上下文，不混合不同模型的健康分母。
3. **多客户端 key** → `09-25-multi-client-key-routing`：管理员维护多个下游 key，每账号恰归属一个 key，鉴权先于账号选租且所有候选、等待、重试、会话绑定/溢出均不得越界；旧 key/账号无缝迁移，管理员凭据独立；密钥不进入非授权投影和普通日志。
4. **全程序性能** → `09-25-whole-service-performance`：覆盖启动恢复、入口解析/鉴权、账号选择与限流、上游连接和流式转发、终态统计/落盘、普通/详细日志、额度后台任务、管理 API 和控制台加载；先做静态热路径盘点与多场景隔离测量，按影响和风险排序，再优化已证实的慢点。300 RPM 仅是其中一种总服务负载样本；不绕过上游账号限额，不把本地实验称为生产保证。
