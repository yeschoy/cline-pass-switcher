# Local raw-body resource observation

On the local Node runtime, a synthetic process retained six simultaneous valid UTF-8 35 MiB bodies in one `CaptureBudget(512 MiB)` and materialized their raw descriptors/text (no upstream, credentials, disk or network). The reservation reached 420 MiB; observed RSS rose from 37 MiB to a peak of 564 MiB. This is an illustrative observation, **not** a process RSS upper bound or production capacity benchmark. Runtime HTTP request parsing, transports, JSON, response buffers, store publication and concurrent admin reads can add substantial memory. At most four concurrent raw body API reads/sends are admitted before metadata queueing and held through HTTP finish/close, but this does not bound total process RSS to 512 MiB. Before production enablement, benchmark multiple concurrent 35 MiB local mock chat/SSE requests and remote-admin body reads under the target container memory limit; fail-open model traffic and bounded diagnostic drops must be demonstrated on that topology. No production enablement or backup/rollback rehearsal occurred here.
