# 错误规则预设、统计面板与健康调度流水线

## Goal

降低账号错误处置配置门槛，提供可信的 token/缓存/账号健康统计，并让账号调度能够按可解释的流水线过滤和排序候选账号。

## Background

- 当前 `accountErrorRules` 由控制台 JSON 文本框直接编辑；服务端支持按 HTTP 状态配置 `ignore`、`cooldown`、`ban`。
- 当前已有 `single`、`roundrobin`、`sticky`、`least-connections`、`weighted-roundrobin`、`priority-failover` 六种互斥账号模式。候选账号会先排除禁用、封禁和冷却账号，但尚无可配置的“过滤 → 健康排序 → 会话粘性”等组合流水线。
- `parseRouting()` 已能读取上游 `usage`，README 明确要求缓存命中只能依据真实 usage 字段；当前账号统计主要暴露请求计数，尚无完整 token 与缓存统计面板。
- 本任务规划开始时存在一组“保留完整长结构化上游错误及安全脱敏”的独立改动；已按用户决定单独提交为 `88a802f`，本任务不得重写或回退该行为。

## Requirements

### R1 — 常用错误规则预设

- 首批提供五个名称与作用清晰的预设：①标准限流保护（429 冷却 30 分钟）；②快速恢复（429 冷却 5 分钟，500/502/503/504 冷却 1 分钟）；③保守保护（429 冷却 60 分钟，500/502/503/504 冷却 5 分钟）；④只观察不处置（429/500/502/503/504 均 ignore）；⑤清空全部规则（仅允许完整替换）。
- 所有自动预设只生成现有 `accountErrorRules` 允许的状态码、动作和冷却时长；服务端现有校验仍是最终边界。自动预设在 4xx 中仅处理 `429`，其他 4xx 可能源于请求参数，不自动冷却或封禁账号；现有综合“保守防封”预设中的 401/403 自动 ban 同步移除，但高级 JSON 仍允许用户自行配置。
- 应用预设时提供“合并（默认）”和“完整替换”两种方式。合并仅覆盖预设涉及的状态码并保留其他自定义规则；完整替换移除预设之外的规则。确认前逐项展示保留、新增、修改和删除，避免静默覆盖。
- 必须完整保留自定义错误规则能力：用户仍可通过高级 JSON 编辑任意服务端允许的状态码、动作和冷却时长；预设只是可选快捷入口，不得限制、覆盖或替代自定义规则。预设与手工编辑使用同一保存路径。

### R2 — 使用量与健康统计面板

- 新增与控制台、请求日志、错误日志并列的顶层“统计”板块；展示累计总量与最近 24 小时两个范围，至少包含请求量、input/output/total token、真实缓存 token 与缓存命中率，以及每个账号的请求、token、错误和健康信息。首期不提供 7 天趋势图。
- token 与缓存数据只能来自上游真实 `usage`；缺失数据必须显示为未知/无数据，不能推算或把会话粘性当作缓存命中。缓存同时展示：`cached_tokens / input_tokens` 的缓存 Token 占比，以及 `cached_tokens > 0` 请求数 / 明确返回缓存字段请求数的缓存命中请求率；缺少缓存字段的请求不进入两个指标的分母。
- 本地统计只计算客户端聊天请求；控制台测试、模型探测、渠道校验、官方模型抓取和额度刷新不进入 token 或健康统计，避免管理流量污染业务健康度。统计同时覆盖非流式和流式请求；重复 finalize、重试、供应商故障转移和账号换号不得重复累计一次请求的最终 usage。
- 统计数据需有明确持久化、重启恢复、旧 metadata 迁移和容量边界；不得记录消息正文、会话值、密钥或原始响应。
- 健康度按最近 24 小时的账号处理结果计算；同一下游请求中同一账号最多记录一次健康结果，供应商内部重试不重复惩罚。分数为 `100 - 加权错误占比 × 100`：成功权重 0，401/403 为 1.0，429 为 0.7，代理/网络错误为 0.6，5xx 为 0.4，其他非参数错误为 0.5；除 401/403/429 外的 4xx 视为请求/参数问题，不进入健康分母，既不扣分也不能被当作成功改善分数。
- 健康状态阈值为：80–100 可用、50–79 降级、低于 50 不健康；最近 24 小时少于 5 个结果显示“数据不足”。禁用、冷却和封禁直接覆盖评分状态。健康度随 24 小时窗口自然恢复；首期不新增统计重置，现有恢复操作仍只解除冷却/封禁。

### R3 — 可解释的账号调度流水线

- 在现有租约、容量和“输出开始后不可重放”约束内提供固定顺序、可开关步骤的流水线：强制排除无密钥/禁用/封禁/冷却账号 → 可选排除不健康账号 → 可选额度热池分层 → 可选按健康度分层排序 → 可选在同一健康层内保持会话粘性 → 使用现有账号模式做最终稳定择优和容量回退。用户不能任意拖拽顺序。
- 流水线每一步的输入、输出、顺序和回退行为必须明确；不得在供应商重试循环中隐式重选账号。
- 调度结果继续记录安全的策略、候选/选择原因和账号路径，不记录原始会话或消息。
- `accountPipeline` 作为现有模式上的可选叠加层；旧配置缺少该字段以及全部流水线开关关闭时，六种 `accountMode` 行为必须与升级前完全一致。`accountMode` 继续负责最终择优/容量回退；现有 `sticky` 模式自动视为启用会话粘性步骤，避免重复执行。新安装默认关闭全部流水线开关，只有用户保存后才改变调度。
- 健康过滤仅移除“不健康”账号；数据不足账号与可用账号进入同一候选层以获得采样机会，降级账号排在其后。若健康过滤后无候选，显式回退到分数最高的不健康账号并记录 `health-filter-fallback`；无密钥、禁用、封禁和冷却账号绝不回退。同层或同分继续由现有模式和稳定账号 ID 决定。
- 配置必须经过服务端严格校验；无有效候选、容量满、健康数据不足及并列情况需有确定行为。高优先级额度/健康层容量满时，`roundrobin`、`least-connections`、`weighted-roundrobin`、`priority-failover` 可立即回退到下一层空闲账号；`sticky` 先等待粘性主账号至 `concurrencyWaitMs` 再溢出；`single` 仍只等待最终选定账号。跨层原因必须记录，硬过滤账号始终不可回退。

### R4 — Cline 额度感知热池

- 已确认 ClinePass 存在 `GET https://api.cline.bot/api/v1/users/me/plan/usage-limits`：使用账号 API Key 的 Bearer 鉴权，返回 `success/data.limits`，已验证类型为 `five_hour`、`weekly`、`monthly`，字段包含 `percentUsed` 和可选 `resetsAt`。官方产品文档确认三种额度窗口，但公开 API 参考未列出此端点，因此按半公开、可能演进的外部契约处理；详细证据见 `research/clinepass-usage-limits.md`。
- 为每个稳定账号 ID 保存严格投影的额度快照、抓取时间与安全错误类别；不得保存请求 Header、账号 Key 或原始响应。未知 limit 类型忽略，已知字段非法时不得覆盖上次有效快照。
- 额度刷新不得阻塞聊天请求关键路径；必须使用有界超时、并发和刷新频率。失败或快照过期时额度状态为未知并回退到普通健康/模式调度，不根据本代理 token 统计推算官方剩余额度，也不据此修改封禁/冷却状态。
- 提供可选“额度热池”流水线步骤。取账号三个窗口中最大的 `percentUsed` 作为最紧张窗口，按 `<80%` 热池、`80%–<95%` 温池、缺失/过期/失败的未知池、`≥95%` 保留池排序；优先从最高层选择，容量满时按 R3 的现有模式语义回退到下一允许层，池内继续执行健康排序、会话粘性和现有账号模式。所有账号额度均未知时等同普通调度，不阻塞请求。

## Acceptance Criteria

- [x] AC1：控制台提供多组常用错误规则预设，可预览后通过现有账号配置保存路径应用，同时保留 JSON 高级编辑。
- [x] AC2：预设不会静默覆盖用户规则，非法规则仍由服务端拒绝且不写入配置。
- [x] AC3：统计板块显示可信的全局和账号级请求/token/缓存指标，缺失 usage 不伪造数据。
- [x] AC4：流式与非流式、重试与换号场景只按定义累计一次，并在重启后保留统计。
- [x] AC5：账号健康状态及评分/排序依据可解释，冷却、封禁、禁用和无数据状态正确呈现。
- [x] AC6：调度流水线能够按确认的步骤过滤、排序并保持会话粘性，结果确定且遵守账号租约与最多一次换号约束。
- [x] AC7：额度后台刷新能够读取并严格投影 Cline 5 小时/周/月限制，按热/温/未知/保留池参与可选调度；接口失败、过期或变化时回退普通调度且不阻塞聊天。
- [x] AC8：旧配置与现有六种模式按确认的兼容策略继续工作。
- [x] AC9：统计、额度与调度 API 不泄露密钥、消息、会话、代理凭据或原始上游正文。
- [x] AC10：相关迁移、集成、UI 契约、语法检查、完整测试和浏览器验收通过。

## Out of Scope

- 基于猜测推算 token 或缓存命中。
- RPM/TPM 限流器、计费金额结算、出口 IP/设备指纹伪装。
- 在没有可验证 Cline 额度接口时推测 5 小时、周或月剩余额度。
- 在供应商重试之间任意更换账号，或在流式输出开始后重放请求。
- 可视化规则构建器以及创建、重命名、删除命名自定义预设；高级 JSON 编辑继续提供完整自定义能力。
- 与已单独提交的“长结构化错误保留”改动无关的重写或回退。
