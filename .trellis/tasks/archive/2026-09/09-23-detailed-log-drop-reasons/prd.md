# 详细日志丢弃分原因计数

## Goal

让操作者能够区分“详细捕获为何受限或未发布”，而不读取/保存任何请求正文、响应正文、Header 值或身份，也不改变现有捕获、脱敏和模型流量行为。

## Background

生产的详细日志 `health.dropped` 在两个只读观察点分别与 `resource-limited` 详情根数一致（208/208、514/514）；`failures=0`、`corrupt=0`，当时普通错误日志为 0。完整详情的一部分正文因安全资源边界被省略，但详情根仍可存在；现有总数把这种情况与发布队列/过期等丢弃混合，无法指出具体限制。只读证据和代码入口见 `research/current-drop-contract.md`。这些计数从进程启动后累计，不代表失败的模型请求数。

## Requirements

1. 保留现有 `health.dropped`、`health.failures`、`health.corrupt` 的含义和 API 字段；在详细日志 health 中增加**固定、有限枚举**的分原因非负安全整数计数，进程重启归零，不持久化、不回填旧记录。
2. 所有当前会让 `dropped` 增加一次的入口必须被一个一致的 owner 收口：每次增加只归**一个主因**，同一时点分项之和严格等于 `dropped`，同一完整详情的多份正文受限不得误算成多次根级丢弃。多重限制同时出现时应有确定性优先级。
3. 原因必须足够区分本次最可能的资源限制来源：捕获内存预算、脱敏秘密集合预算、脱敏扫描/深度工作量、文本/输出预算、活动/attempt 数量上限，以及发布队列、过期/代际、open-root 关联、大小/存储准入等。未识别情况用一个固定 `other` 桶，不生成正文或动态标签。
4. `GET /api/logs/settings` 与 `GET /api/logs/details` 复用现有认证和 health owner 返回这些**聚合数值**。普通请求/错误 JSONL、metadata、详细 manifest、错误响应及服务日志均不增加单请求原因或任何正文/凭据/会话信息；旧客户端可忽略新增字段。
5. 控制台“详细日志”页在既有 `DETAIL_*` 状态/`api()` 内显示非零原因及进程启动以来的总数口径；使用固定中文标签和 `textContent`/ARIA live，缺旧字段时安全显示未知或无分项数据，不影响账号草稿、导航、游标和两种日志开关。
6. 保持现有 5 MiB 单正文/64 MiB 捕获保留预算、脱敏安全挡板、失败隔离、存储保留和写入时序；不为了提高完整度放宽限制，不改变模型响应、重试、RPM、租约、统计或 shutdown。
7. README 和 backend/frontend 英文 spec 同步字段口径、常见原因与可验证边界；只用临时 DATA_DIR/local fixtures 测试，不访问真实上游或生产数据。

## Acceptance Criteria

- [ ] 空 store 与默认关闭模式的 `dropped=0`、全部固定分项为0；触发任意入口后 `sum(dropReasons)===dropped`，包括同一 root 多 body 受限、并发拒绝、存储队列/容量/代际/关联拒绝。计数不因普通请求成功或浏览器读取增加。
- [ ] 聚焦测试以小型可控预算分别触发 capture budget、redaction secret、redaction work/output 和至少一种 store admission；分项精确且只计一次，多个原因时主因稳定。普通 5 MiB 截断（未触发资源限额）不误归入丢弃。
- [ ] 既有 `failures`/`corrupt` 与 `dropped` 独立；落盘/发布失败仍 fail-open，不泄漏资源或改变聊天响应。安全整数在上界处不溢出、不破坏分项总和。
- [ ] 认证 API 两处 health 投影一致，仅固定原因键+安全数字，无正文、Header 值、账号 Key、原始会话、requestId 或每请求明细；旧记录无需迁移，重启分项归零。
- [ ] 生产内联脚本 VM/UI 测试证明“详细日志”原因显示安全、有界、可访问，缺字段兼容；真实浏览器在窄宽度验证阅读与焦点/ARIA，而不把 VM/静态证据冒充浏览器。
- [ ] 聚焦存储/捕获/UI/集成测试、语法、内联脚本编译、完整项目门禁和 `git diff --check` 全通过（基线 242 个用例不得删除或跳过）。

## Out of Scope

- 改动详细日志开关、默认模式、阈值、脱敏策略、存储保留或生产设置。
- 读取或分析生产正文以猜测具体哪条规则被触发；本次只建立未来可观测性，不追溯历史 `dropped`。
- 单请求原因列表、持久化计数、跨进程汇总、新监控服务或新依赖。
- 自动部署/推送到生产；需要后续单独授权。
