# 兼容纳秒额度重置时间

## Goal

兼容 Cline 当前使用的纳秒级重置时间，恢复账号 5 小时、周、月额度展示与额度池路由。

## Background

- 线上只读探测确认额度端点返回 HTTP 200、合法 JSON、`success: true`，`data.limits` 含 `five_hour`、`weekly`、`monthly`。
- 当前返回的 `resetsAt` 示例为 `2026-09-16T01:41:26.552188975Z`；JavaScript 可解析并规范化为 `2026-09-16T01:41:26.552Z`。
- `server.js:311-313` 当前正则仅允许 1–3 位小数秒，导致 `parseQuotaPayload()` 在有效额度值存在时仍将整次结果标记为 `schema`。

## Requirements

- RFC3339 重置时间接受 1–9 位小数秒以及既有 `Z`/数值时区形式。
- 接受后统一输出 `Date#toISOString()` 的毫秒 UTC 格式，保持持久化快照契约不变。
- 继续拒绝无效日期、无时区、超过约定精度或其他非规范时间。
- 不放宽额度值 0–100、窗口类型、重复窗口、响应大小、认证、代理、超时和敏感数据规则。

## Acceptance Criteria

- [x] AC1：1、3、6、9 位小数秒的有效时间均被接受并规范化为毫秒 UTC。
- [x] AC2：真实 9 位线上示例可与三个额度窗口一起生成成功快照。
- [x] AC3：无效日期、无时区和超过 9 位小数秒继续返回安全 `schema`，且不覆盖上次成功快照。
- [x] AC4：统计页显示三个额度比例与规范化重置时间，额度状态不再因该格式显示“数据格式”。
- [x] AC5：额度刷新并发、退避、缓存、generation fencing 和聊天 fail-open 行为保持不变。

## Out of Scope

- 改变额度端点、池阈值、刷新调度或 UI 布局。
