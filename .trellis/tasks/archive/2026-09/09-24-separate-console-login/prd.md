# 管理网页独立登录与 API 密钥分离

## Goal

管理网页有独立于模型客户端 API key 的登录凭据和服务端授权；拿到模型调用密钥不等于取得管理权限。

## Background

- 当前 `PROXY_KEY` 同时允许 `Authorization: Bearer` 或 `X-Admin-Key` 访问 `/v1/*`、`/api/*` 与聊天别名；空 key 时全放行（`server.js:1789-1801,4090-4102`）。
- 网页端把同一明文密钥保存在 `localStorage.cps_key`，发到每次 API 的 `X-Admin-Key`；登录只测试 `/api/models` 是否成功（`public/index.html:381-405`）。因此单纯换登录弹层不能完成权限隔离。

## Requirements

- 客户端 API key 仅允许模型代理及明确保留的公开元信息；管理端独立验证/会话才能访问账号配置、日志、统计详情、额度刷新、安全设置等敏感 API。
- **已确认产品选择**：使用本地单管理员密码；升级/初始化时以当前生效的代理 API key 作为管理员初始密码。支持远程网页登录完成**首次一次性初始化**：验证当前 API key 与独立的一次性初始化码，随后强制修改管理员密码，完成前不能访问其他管理 API。后续改管理员密码不应轮换客户端 API key；初始值只作为一次性迁移种子，不得持续将 API key 当管理鉴权凭据或在改密后再次同步/覆盖。
- 新登录状态需可过期、退出和吊销，页面不应持久保存管理明文凭据；服务端严格限制 Cookie/CSRF/XSS、跨源请求和未登录时的敏感读取/写入。不得将客户端 Authorization 透传上游。
- 既有部署的凭据迁移、首启初始化与回滚要明确：不能暗中保留旧 API key 可管理的后门，不能把合法操作员锁在外面。一次性码只用于首次启用独立管理员登录；凭据状态在 `DATA_DIR` 安全持久化，正常升级/重启不重复初始化，状态丢失/主动重置另走受信恢复流程。必须处理代理 API key 为空或由环境变量覆盖的情况；空 key 不能成为空口令管理员。
- 保持模型客户端合法请求与管理 UI 可用，自动化测试使用临时 DATA_DIR 和假凭据，不操作生产服务或真实登录状态。

## Acceptance Criteria

- 仅持有客户端 key 的主体无法访问或修改任何敏感管理 API；管理者登录/登出/过期/吊销按预期工作，非法或跨站请求失败且不泄露秘密。
- 空旧 key、旧本地存储、已有管理访问方式、重启、密钥轮换和迁移路径都有明确的兼容/失败行为；完整端点矩阵覆盖所有管理路由，不仅首页。
- 浏览器登录对键盘与小屏友好，敏感内容不被页面缓存或 XSS 不安全投影泄露；兼容部署有可执行回滚说明。

## Scope assumptions for design review

- 客户端 key 为空的新装实例不能使用空管理员密码：管理员初始化需另配非空的一次性受信凭据。一次性码从独立于客户端 API 的运维配置通道提供，不进入普通日志、API 投影或页面持久存储。生产环境覆盖、重启、回滚和既有管理脚本迁移在设计/实施清单中明确；不保留旧 key 作为管理后门。
