# 支持拖动排序账号流水线

## Goal

让操作者可以将 `excludeUnhealthy`、`quotaPool`、`healthSort`、`sticky` 四个可选账号调度步骤任意拖动排序，并让保存顺序真实决定账号选择优先级。

## Background

- 当前配置只保存四个布尔值，`server.js:587-650` 固定按健康过滤、额度池、健康分层、会话粘性执行。
- 当前 UI 在 `public/index.html:213` 使用固定顺序复选框；账号加载、原始调度草稿和保存路径分别在 `public/index.html:481-486,838-906`。
- 强制资格过滤会移除无 Key、禁用、封禁、冷却和当前请求排除账号；它不是四个可选步骤之一，必须继续最先执行且不可回退。
- `accountMode=sticky` 当前会隐式启用粘性；四项全关时走独立 legacy 快路径以保护六种账号模式。

## Requirements

### R1 — 排序配置

- 四个步骤在保存顺序中各出现且仅出现一次；启停状态与顺序独立保存。
- 旧配置缺少顺序时使用 `excludeUnhealthy → quotaPool → healthSort → sticky`，保持升级前行为。
- 管理 API 对顺序类型、未知步骤、重复、缺失严格校验；失败不部分写入。
- 旧客户端省略顺序字段时保留当前已保存顺序，不静默恢复默认值。

### R2 — 执行

- 后端按持久化顺序组合过滤、分层和粘性步骤，执行结果确定且可测试。
- 顺序越靠前优先级越高；后续步骤只能在前一步形成的同级候选组内继续细分，不能跨越前置优先级。
- `quotaPool → healthSort` 时额度层优先，`healthSort → quotaPool` 时健康层优先；sticky 位于前部时，其 HRW 顺序优先于后续分层。
- 硬资格过滤固定最先；最终账号模式、容量等待、租约释放、供应商重试和最多一次账号替换继续遵循现有边界。
- `accountMode=sticky` 与可选 sticky 步骤不得重复执行；未显式启用 sticky 时仍保留既有隐式粘性兼容行为。
- 四项全关时忽略顺序并进入原 legacy 选择器。

### R3 — UI 与草稿一致性

- 四个步骤均有拖动手柄、启停控件、当前位置编号和明确的拖动反馈。
- 提供键盘可操作的等价排序方式；不能只依赖鼠标拖拽。
- 加载、拖动、原始配置应用、保存失败/成功和重新加载均保持单一调度草稿，不覆盖账号、错误规则或其他未保存修改。
- 原始调度编辑器展示和校验同一顺序字段。

### R4 — 诊断与安全

- 现有有界流水线诊断继续反映选择层、容量回退和安全枚举，不记录原始会话、额度响应或凭据。
- 调度变更不得阻塞聊天等待额度刷新，也不得放宽硬过滤或在供应商重试中隐式重选账号。

## Acceptance Criteria

- [x] AC1：四步骤所有代表性排列均按保存顺序产生预期候选优先级；重启后顺序不变。
- [x] AC2：额度优先与健康优先的冲突样例选择不同且符合已确认的优先级方向。
- [x] AC3：sticky 位于首、中、尾时行为明确；有/无 identity、六种 accountMode、容量满与跨层回退均有回归覆盖。
- [x] AC4：旧配置、旧 API 负载、非法顺序、四项全关和 `accountMode=sticky` 兼容测试通过。
- [x] AC5：鼠标拖拽和键盘排序均更新编号及草稿；保存失败不改变服务端配置，成功后刷新/重启恢复。
- [x] AC6：原始配置编辑器与可视控件双向一致，账户完整快照和其他草稿字段不丢失。
- [x] AC7：日志、安全、租约释放、账号替换和聊天关键路径测试保持通过。

## Out of Scope

- 拖动强制资格过滤或最终账号模式。
- 自定义额度/健康阈值、评分公式或新增步骤插件系统。
- 为流水线引入第三方拖拽依赖。
