# 模型价格、简洁统计、多客户端密钥与性能优化

## Goal

在现有 Cline Pass 代理上分四项独立交付：扩大有依据的模型**参考用量等值**覆盖、简化模型/渠道统计页、按客户端 API key 隔离账号调度，以及面向全服务约 300 RPM 的可测热路径优化。父任务只统筹需求和跨项验收；不直接实施代码。规划评审前不启动实施。

## Background / confirmed facts

- 用户第一张截图与归档 `.trellis/tasks/archive/2026-09/09-24-model-provider-statistics/research/official-pricing-and-usage.md` 的 ClinePass 官网价格表行一致。来源 `https://docs.cline.bot/getting-started/clinepass` 标为 USD / 百万 Token **参考费率，非包月订阅实际逐 Token 扣费**；官网未注明逐行生效日，本项目既有采集日 2026-09-24。实施前再核对官网现价，保留内部采集时间/版本与旧快照。
- `server.js:872-910` 当前只给 Kimi K3、GLM-5.3、DeepSeek V4 Flash/Pro 估值，后两者为峰谷参考区间；版本化历史已冻结。`normalizeUsage()`（`server.js:2412-2425`）没有 Cached Write 计数和上下文档位；不能凭截图为 Qwen 等模型捏造完整金额。`cline-pass/glm-5.3-flash` 不是官网定价行 `cline-pass/glm-5.3`。
- `public/index.html:160-168,1356-1405` 将模型最终请求与渠道真实尝试、最终成功 usage、价格版本和覆盖警告混入一张大表。用户要求拆成“模型”“渠道”子标签并压缩默认展示；建议把模型列叫“请求成功率”、渠道列叫“渠道尝试成功率”，每格仅显示 `百分比 · N 样本`，把“最终请求”等口径说明放在简短帮助中，保留未知/覆盖详情入口。
- `server.js:1935-1942,4588-4599` 目前只接受单个客户端 `PROXY_KEY`；独立管理员会话已交付，客户端 key 不能访问管理路由。`POST /api/security` 和控制台安全区仍管理单 key；`acquireAccountLease()` 当前从全账号池选取（`server.js:1910,4271-4320`）。用户确认**每个上游账号只属于一个客户端 key，不在 key 之间共享**；所有现有账号归属现有 key。
- 用户提的“300 RPM”是**全服务未来性能参考负载**，与单 key 配额无关，不要求新增 per-key 限流。现有 `maxRpm` 按上游账号/真实 Provider attempt 限制，`maxConcurrent` 限在途账号 lease；RPM 不等于并发。`pruneStatistics()` 在请求终态扫描最近 24h 桶并且 `record()` 同步落元数据（`server.js:2489-2567,2739-2832`），是测量候选，尚未证实为 300 RPM 瓶颈。普通 JSONL 已有有界队列；归档 5 MiB 脱敏样本约 118 ms event-loop p99 不是目标负载/容器验收数据。仅在隔离本地模拟上游中压测，生产需单独授权。

## Requirements and child ownership

1. **参考费率** → `09-25-expand-reference-prices`：按官网价格/模型 ID 扩展可靠计价的单档及区间模型；不能估值的模型展示表中单价与不可计金额原因，历史版本不重算，明示非实际扣费。
2. **管理台** → `09-25-simplify-model-provider-console`：两个子标签分别展示最近 24h 模型/渠道，默认表格只保留简洁的成功率、关键用量/缓存与金额；详情按需展开，未知与覆盖不能伪装成零或完整。渠道维度保留模型上下文，不混合不同模型的健康分母。
3. **多客户端 key** → `09-25-multi-client-key-routing`：管理员维护多个下游 key，每账号恰归属一个 key，鉴权先于账号选租且所有候选、等待、重试、会话绑定/溢出均不得越界；旧 key/账号无缝迁移，管理员凭据独立；密钥不进入非授权投影和普通日志。
4. **性能** → `09-25-service-300rpm-performance`：先用 temp `DATA_DIR`/mock upstream 建立全服务聚合 5 req/s 左右的可复现基线，再按证据优化现有 owner；报告吞吐、延迟、事件循环、RSS/CPU、错误/诊断丢弃及工作负载边界；不绕过上游账号限额，不把本地实验称为生产保证。

## Cross-child acceptance

- [ ] 价格版本、未知值、缓存/峰谷语义从后端到统计 API/浏览器一致；改价不重估旧请求。价格子任务在页面文案验收前交付或页面兼容新旧快照。
- [ ] 模型/渠道页面在无样本、失败重试、未知渠道、缓存缺失、迁移未满 24h 时简洁但不误导，真实浏览器验证键盘/焦点和窄屏。
- [ ] 老配置/旧 key/原账号迁移和重启往返；新旧 key 互不能租用对方账号（含粘性、缓存池、前置换号、管理测试路径区分）；禁用/轮换/删除/空账号池按可解释的安全规则处理。完整账号保存不丢隐藏字段；管理员认证/首改密不回退。
- [ ] 300 RPM 是全服务隔离测试用的容量参考。先量后改、同条件复测；不能达到的场景列真实阻碍和后续优先级，绝不暗中调整账户限制或承诺生产 SLO。
- [ ] 每子任务独立测试/审查/提交，父任务最后做跨功能复核；与 `09-24-diagnostics-quota-console-plan` 已实现统计/独立登录约定兼容，不重开原文日志和生产验收门禁。部署、生产密钥和付费上游操作不在本次授权内。

## Out of scope / assumptions

- 本次不做真实订阅账单结算、跨 key 账号共享、分布式多副本硬 RPM 限额、按 key 独立 300 RPM 目标或大规模架构替换。
- 性能压测默认单进程/本地 mock、短响应与有界 SSE/慢响应组合，时长覆盖多于一个 60s 窗口；其结果只代表该环境。若后续需要生产负载 SLO、目标机器参数或真实上游实测，另行明确与授权。
