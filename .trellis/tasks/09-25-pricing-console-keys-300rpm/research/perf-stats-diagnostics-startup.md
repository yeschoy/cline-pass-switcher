# 性能审查：统计、诊断、额度与启动（只读，当前源码）

范围：本次仅审查 `server.js`、`lib/`、相关测试/规范及既有**归档**本地实验；未读取运行配置、生产数据，未跑当前负载实验。下列“候选”均不是实测瓶颈。记 `B≤1440` 为分钟桶数，`C` 为桶内各类统计单元总数，`M` 为统计页模型数，`P` 为某模型渠道数，`S` 为普通日志段数，`R` 为恢复记录数，`D` 为详细日志目录/索引数，`A` 为账号数。上界由不同 cell 限额约束，并非各限额可以无代价同时取满。

## 已解决的旧慢点 / 当前已有防护

- **普通日志旧全量写路径已替换**：`lib/jsonl-log-store.js:126-157,208-288` 异步启动恢复，按段存轻量目录；`lib/jsonl-log-store.js:337-415` 先序列化、限每条 64 KiB/待写 10k 条或 16 MiB，串行异步写活动段，超限诊断丢弃而非压住业务；`lib/jsonl-log-store.js:417-493` 以目录计数作阈值/定时维护，只重写边界段。启动前不扫描旧语料；恢复中普通日志查询 503、请求仍可入队，失败 fail-open。`test/jsonl-log-store.test.js:37-73,110-117` 覆盖异步恢复、当前就绪追加不扫描历史、边界段读和容量护栏。旧本地 5k 条对比 3607.9→70.58 ms 属于归档 `.trellis/tasks/archive/2026-09/09-19-optimize-ordinary-jsonl-logs/research/local-performance-validation.md`，**不能当作当前整机结果**。
- **详细日志旧每次全盘扫描已替换**：`lib/detailed-log-store.js:153-174,347-402` 索引有 100k 条/64 MiB 上限，`publish/query/expire` 用内存索引与串行队列，整盘 `reconcile` 留在启动、故障恢复和小时维护；原始目录有独立 TTL 与所有权检查（`lib/detailed-log-store.js:205-276,317-360`）。归档 `.trellis/tasks/archive/2026-09/09-18-optimize-detailed-log-scan/research/local-performance-validation.md` 的 5k 根启动 ~689 ms、查询 ~2.77 ms，仅为当时本机合成样本。
- **详细抓取有模式及预算**：默认 off（`server.js:55-57`）；`server.js:4560-4573` 请求路由 opt-in、最多 128 活跃 root；`lib/detailed-log-capture.js:34-43,351-374,467-485,511-553` 限抓取量/5 MiB 单体、先发现秘密再投影，error-only 成功请求不持有完整采集体；`lib/detailed-log-store.js:395-402` 最多 128 待发布。历史 5 MiB 脱敏 ~118.36 ms event-loop p99 是归档 `.trellis/tasks/archive/2026-09/09-21-error-detail-log-performance/research/performance-validation.md` 的单机微基准，不是当前容器、整机、或默认关的运行证据。Promise 串行化并不把脱敏 CPU 移出事件循环。
- **统计/价格与额度有语义护栏**：`server.js:885-910,919-960` 价格快照有 8 版本/16 模型校验、金额 BigInt 溢出置未知；`server.js:2542-2564` 保留被单元引用的旧版本，新版本容量满时标记覆盖缺口，不能通过重算旧价优化。额度同一账号合并作业、全局最多 2 并行、超时/退避、代际取消（`server.js:3112-3124,3188-3269,3271-3303,3382-3404`），不是无限并发请求；静态配额和 RPM 语义不能为测速绕过。

## 尚存候选及复杂度（按预期影响 *待测排序*）

1. **请求终态：双次剪枝 + 全 metadata 同步原子重写**。`server.js:2567-2615` 每次 `commitStatistics` 前后调用 `pruneStatistics`；`server.js:2489-2543` 各遍 `B` 桶及其账号/模型/Provider/用量/价格单元，并为每个非当前价格版本 `some` 扫价格单元，约 `O(B+C+V·C)` 每遍，且每次构造数组/对象键。`server.js:2739-2833` 每次 `record` 投影请求及失败尝试、异步排普通 JSONL，然后 `saveMeta`；`server.js:112-151` 在事件循环同步 `JSON.stringify(META,null,2)`、stat、写临时文件、rename，时间/分配随当前 metadata 字节数线性增长且每次终态重写。记录失败仍 fail-open，但同步调用仍阻塞其他请求；不可只因 300 RPM 猜测它是第一瓶颈。应先量剪枝两次分别耗时、metadata 序列化/写/rename 时间与字节、终态占响应延迟和 loop delay，并在稀疏/满窗/高基数元数据上比较；保持原子持久化和 coverage，不可直接定时丢写。
2. **管理统计页投影乘法扫描**。`server.js:4778-4784` GET 先剪枝，再对每账号 `aggregateRange` 和 `healthProjection`，对每模型 `aggregateModelRange`、`modelProviderProjection`；`server.js:2616-2709` 每模型多次扫描 `B`，每渠道分别调用 `providerUsageProjection`（使用量+价格）与 `successHealthProjection`，约 `O(B·(A+M+ΣP))` 加上枚举模型/单元 `C` 与输出体大小。价格版本投影自身按存在的单元累加，不是逐请求动态查官网。对稀疏与 1440 桶、多模型多渠道、高 A 数据，测独立 GET CPU/延迟、响应 bytes/内存峰值，并与并行聊天一起跑；勿将页面表格渲染成本归咎后端。
3. **异步日志仍可能有队列/维护和冷读成本**。`lib/jsonl-log-store.js:345-414` 每 append 的 `_recordCount`、`_totalBytes` 都折算全部 `S` 段 (`O(S)`)，阈值后串行维护；`lib/jsonl-log-store.js:208-288` 冷恢复读/解析最多 128 MiB/120k 记录、目录上限 10k；`lib/jsonl-log-store.js:502-548` 查询新段优先，稀有筛选/深游标可能读完有界语料并排序，`parseBuffer` 每 1000 行 yield (`lib/jsonl-log-store.js:42-61`)。量 ready 追加与段数关系、恢复至查询可用时间、带过滤冷读/目录饱和、队列等待及 `health.dropped/failures/pending`，模拟慢盘/错误；不要恢复旧全量同步压缩。
4. **详细模式仍可能有 CPU/目录排队**。`lib/detailed-log-capture.js:150-244,351-445,527-550` 完整 body/SSE 多次 JSON 解析、秘密学习和逐片 materialize；`lib/detailed-log-store.js:59-76,395-452` serial 保证一致性但 `produce()` 的脱敏同步执行，单 root 最多多个尝试/正文文件，发布 `expire/admit` 与管理查询共队列；`lib/detailed-log-store.js:174-183,371-393,451-452` 容量逐出时 `oldest()` 全索引 `O(D)`，高占用下重复；定时每分钟 expire、每小时 reconcile (`lib/detailed-log-store.js:54-55,205-276,317-360`) 可能放大目录 I/O。完整扫描不读取正文但 stat 文件和读 manifest；启动 `startup()` 在构造后异步运行，却会与首批请求竞争磁盘/事件循环。分别测关闭、error-only 成功/失败、full 短/5 MiB SSE、raw（仅隔离获准测试环境，不启用生产）、D 大小和慢盘，记录 dropped 原因/预算/RSS/loop delay/队列耗时；避免以归档 sanitizer p99 外推所有模式。
5. **额度轮询及同一 metadata 写盘竞争**。`server.js:3420-3452` 路由开启时周期唤醒（约 1–30 秒轮转），每轮 HRW 排序账号并筛 due `O(A log A)`，取最多 2 个；`server.js:3271-3303` 每个完成（成功或失败）都 `saveMeta()`，若同时完成会串行占事件循环，与 chat 终态争同一 JSON 文件；`server.js:3429-3441` 禁令持久化失败走定时重试。管理手动刷新 `server.js:4755-4776` 可对全部账号排队、有并行/页面上限。单独量启用/关闭路由、A 大小、模拟额度响应快/超时/失败、后台定时及手动 refresh 与聊天并发时的 loop delay、写盘次数/字节、quota queue depth，保护状态一致性与 fail-closed 禁令。
6. **启动恢复/迁移的同步阶段**。`server.js:104-146,1110-1177` 在监听前同步读/解析配置与 metadata、校验统计全桶/价格版本及迁移，脏状态同步 `saveConfig/saveMeta`；`server.js:974-1059` 逐单元验证，约 `O(B+C)`；输入损坏拒绝并保留原文件，不能为启动速度跳过校验。普通/详细日志构造开启异步恢复 (`server.js:153-160`; `lib/jsonl-log-store.js:208-288`; `lib/detailed-log-store.js:317-360`)，监听见 `server.js:5083-5094`；监听可早于日志 API ready，但后台恢复并非零资源。测 spawn→listen/首个 `/api/meta`、首个真实 mock chat、两日志查询分别 ready、同步迁移成本与恢复期间 CPU/RSS/loop delay；配置新装/旧版迁移/最大合法孤立合成数据分开，勿使用真实文件。`server.js:4603-4605` 控制台 GET 仍同步读 HTML，是另一个跨范围低优先候选，可用页面重复请求独立验证。

## 可复现实测建议与判定边界

- 用**同一提交和环境**生成可公开合成配置/旧版合法 metadata、普通段及详细 manifest 于临时 `DATA_DIR`，本地 mock 上游/代理；请求/错误日志不得含秘密、body；不要读取默认仓库 `config.json`/`metadata.json`/`data/`。隔离冷启动、空/中/近上限统计桶及日志目录、普通/详细诊断开关和额度刷新场景；记录输入规模与配置上限，先测当前整合后的 baseline 再动代码。
- 将 `perf_hooks.performance` 分段打点或 CPU profile、`monitorEventLoopDelay`/eventLoopUtilization、`process.cpuUsage`/RSS/heap 与外部客户端单次及 p50/p95/p99、达成吞吐/错误码并记；区分请求终态到诊断 drain、fs 写入计数/耗时与业务响应。轮询管理读、多并发和慢 SSE/慢消费者单列；5/s 超 60 秒只是一行样本，需有低并发、数据规模、burst 和 I/O 最坏情形。相同 synthetic corpus、诊断配置、upstream 响应和机器上复测优化前后；同时断言价格旧版/coverage/未知、原子失败恢复、额度状态与 JSONL/detailed 丢弃量不恶化。
- 此文件为静态盘点，**没有新的测量结果或当前性能承诺**。归档实验只说明某类旧热路径已改造，不能证明当前服务、目标容器或 300 RPM 稳定性；生产负载/凭据/部署另需授权。
