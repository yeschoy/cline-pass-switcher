# Cross-deliverable design map (planning)

## Boundaries and order

The parent is coordination-only. Pricing and UI share the existing `server.js` statistics / `public/index.html` read-only projection: freeze a new reference price version before final UI wording, but UI can consume old and new versions without destructive API changes. Multi-key routing owns `server.js` authentication, config/account normalization and the current account-selection/lease paths; do not develop it concurrently with other `server.js` writers. The performance child measures an integrated baseline after pricing/multi-key changes but before any performance optimization; an earlier current-HEAD exploratory baseline is optional and must not be compared as if configuration/schema were identical. Optimize only independently proven hotspots; sequence implementation commits to keep rollback possible.

## Contract intersections

- Prices are published tariff facts; valuation remains a frozen approximate usage equivalent in USD, never a real subscription bill. A tariff row may be visible even when a complete amount is unavailable. Use the existing versioned statistic cells and retention/overflow coverage. No automated paid price fetch, new billing store, or backfill of historical unpriced usage.
- The model tab uses one final-request sample per resolved model. The channel tab uses `(resolved model, named Provider)` real attempt health samples and final-success attributed usage (plus explicit unknown-Provider usage). The API already projects these; do not make a new statistics store or silently sum failed retries into usage. Move verbose version and coverage explanation into an accessible expandable detail tied to its row; preserve source link and effective-date uncertainty.
- Client key authentication yields an internal stable key ID, not a raw key attached to request logs/statistics/body. Filter candidates by that key ID **before** any legacy/pipeline/cache pool/stateful-binding ranking, waiting, standby expansion or pre-stream replacement. A shared session fingerprint must not reuse a binding from another key; scope its in-memory identity and invalidate on ownership changes. Account `.key` stays the upstream credential and must never be confused with downstream key ID. `activeAccount` single mode needs a deterministic in-scope fallback if global active belongs to another key; empty in-scope pool fails closed without borrowing. Management probes/tests using explicit account IDs remain independently admin-authorized, not client-key-routed.
- Preserve the old `proxyKey` and environment `PROXY_KEY` startup override as an explicit *legacy key* compatibility boundary. Decide one canonical persisted key inventory and key-ID migration without duplicate mutable secret owners. An empty legacy key currently means open model traffic; retain it for a legacy installation until an admin explicitly configures authenticated keys, after which unknown credentials must fail closed. Account full-list saves and key management must validate foreign IDs, deletion with attached accounts, rotation, re-login, admin-password equality and persistence before mutation. Never turn a client key into an administrator login path. New secrets should be shown only when created/rotated, with admin UI labels and safe masked projections; do not print or fixture real keys. Existing older clients may depend on `/api/security.proxyKey` and need an explicit compatibility test if shape evolves.
- New keys affect all credential scrub lists (`boundedProviderNote`, `safeReason`, diagnostic capture/Headers) and catalog/model routes. User-facing auth failures must not reveal whether a key ID exists. Safe optional bounded key ID/name projections need cross-layer audit: metadata, JSONL, detailed manifests, statistics, config APIs, public meta and source. An in-flight request may finish on its already leased account when an admin rotates a key, while *new* admission immediately uses the new inventory; no replay or cross-key reassignment.

## Performance experiment and rollback

Use a deterministic local mock upstream, isolated temp `DATA_DIR`, authenticated synthetic keys, configured account capacities and representative bodies; inject open-loop paced arrivals at 5/s for more than one rolling 60s window plus bounded burst and stream/slow cases. Record achieved/target RPM, result/error distribution, client latency p50/p95/p99, event-loop delay, RSS/heap, CPU, metadata size/write frequency, queue drops and live concurrency. Separate local service capacity from upstream quota/account-RPM blocks. A suspected `pruneStatistics()` repeated full scan + `record()` synchronous same-directory atomic metadata rewrite is **only a profiling hypothesis**. Optimize the current statistics/persistence owner if evidenced, retaining atomic durable truth and fail-open traffic on diagnostic failures; no generic queue, second store, weakening stats coverage or blanket disable of logs. Rerun identical workloads and targeted failure/restart/SSE cancellation tests. No production load, privileged credentials, raw-body enablement or release operations without separate authorization.
