## 分层结论与建议

1. **已证实排除的解释（仅限唯一关联的请求）：**第一张长名单是候选，该请求仅一次成功 Switcher 尝试，无账号切换；周边 21 条同模型日志也都同一匿名账号、同一目标且每条一条成功 trace。这排除了把该行的 15 个候选当作 15 次 Switcher 重试；第二张其余行未唯一关联，不能把周边日志直接当作上框对话路径。
2. **已证实但解释有限：**较晚探索窗相对较早发布后窗的布尔命中率降低，聚合 Token 占比却上升；已知缓存未命中集中在 `message_hmac` 回退流量。这是关联性和流量组成线索，不证明回退身份造成未命中。第二张图两框对话的缓存 Token 量差异不能由普通日志定量逐条解释；时间相近的 binding miss 因果也未证实。
3. **后续排查优先级（均为待证假设，不是原因概率排序）：**先以安全关联 ID 核对两对话各次计量定义、输入/缓存 Token 及实际输入变化；再比较同一请求的匿名账号、目标/可观测最终 Provider、绑定/上游键枚举，判断身份传递或路由是否漂移；最后核实远端缓存策略/网关内部行为。稳定前缀变化、New API 未传稳定身份或远端缓存键、网关缓存/Provider 内部路由变化都尚未证实。此处仅请求原计量系统的脱敏投影或另行授权的最小诊断，不读取/导出对话正文，不建议贸然改生产路由或回滚。
