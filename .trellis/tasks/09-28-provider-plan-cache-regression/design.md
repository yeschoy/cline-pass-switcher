# 只读缓存归因设计

## 边界与证据等级

1. 本地源码/测试解释字段语义；历史部署研究仅提供上次已知版本和时间边界，不能证明当前生产仍相同。
2. 生产只读数据优先通过现有已认证管理员会话读取普通请求日志与统计；如无会话，先确认用户授权的安全只读途径。任何读取都限定为服务端安全投影，筛选/计数尽量在受控环境内完成，只保留匿名聚合和必要的单请求诊断。不得把身份凭据、请求体、整个 operator JSON、原始日志带回仓库。
3. 运行版本证据以生产当前 image/release、启动时间与配置关键字段的安全投影为准；再按已记录的发布、重启、配置和统计 schema 边界切窗。不能确认的边界不填补。

## 数据流与口径

- 双对话个案：先把两红框各请求的本地时间转换 UTC，以模型、时间、请求 ID（若跨系统有相关 ID）和安全路由事实关联；时间相近不等于同一调用，关联不唯一时停止逐行归因。优先在原图/已认证的计量界面核对逐次 cachedTokens、输入 Token 定义和范围，再与 Switcher 的 `cacheHit`、`bindingResult`、`actualProvider`、`attempts`、账号匿名一致性等安全普通日志投影对照。切勿把 New API 显示的缓存 Token 数盲目当作 Switcher 的输入 Token 或把两界面百分比直接相除。诊断字段说明：`cacheHit === true` 仅证实缓存 Token > 0，不说明缓存量占比。
- 单请求：按第一张截图 ID 只读查询普通请求行，读取 `targetProviders.length`、`attempts.length`、尝试状态和 Provider、`actualProvider`、`switched`、`cacheHit`、`bindingResult`、`providerPlanSource`/`providerMode`。UI 列只显示候选。`/api/logs/errors` 可用相同 ID 核对失败尝试，但不是所有成功尝试的账本。不要读取详细正文。
- 群体：以 UTC 时间窗从现有普通请求记录计数 `cacheHit === true|false|null`，仅 true/false 是命中率分母；统计的 `cacheTokenRatio` 仅从具备同窗口语义且覆盖完整的分钟桶/安全聚合取得，不从请求行杜撰 Token 数据。多尝试比例以 `attempts.length > 1` 在可比较请求中计数，按模型/池/流式等维度审查混杂。普通日志受 30 天、50,000 行/100 MiB 及分页限制，缺行/不可读取不能当作零。
- 窗口：先做较短、相同时长的发布前后探索性窗口（必要时匹配时段/模型/owner），并标注预热、流量混合与策略差异；正式 24 小时政策验收须遵循原任务的 2 小时预热、连续 24 小时及 ≥1000 明确 cache 样本等护栏，不能把探索性对比当验收。`recent24h` 只用于背景，不直接作 post-release 指标。

## 取舍与停止条件

- 优先复用现有受保护 API/诊断投影，不增设脚本、端点、数据导出或持久化 owner；若历史分钟桶不能按准确窗口安全投影，可只报请求命中率，并将 Token 对比标记不可得。
- 版本、管理认证、可比窗口、覆盖或足够样本任一关键条件缺失，输出范围受限的结论和所缺数据，不臆断因果。
- 本任务不包含生产配置变更、发付费请求、部署、回滚或代码改动；发现缺陷仅形成建议，后续另行决策。
