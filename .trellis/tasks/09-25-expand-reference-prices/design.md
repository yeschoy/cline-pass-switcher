# Price extension design

Keep `REFERENCE_PRICE`, `referenceValue()`, v5 valuation minute cells and `referencePrices` API in `server.js` as sole owners. New immutable internal v2 snapshot holds all 13 verified tariff rows; historic v1 `priceVersions` remain valid and frozen. Existing v1 schema only allows `single` or peak/off-peak rate triples in integer thousandths. Validate historical v1 as-is, and validate v2 with explicit `rateScale: 10000` (rates in ten-thousandths USD / 1M Token), optional Cached Write column (`null` means the tariff shows `—`) and explicit `context-band` for Qwen3.7 Plus. All 13 fit the current 16-model cap. This scale exactly represents `0.0028`, `0.0145`, and `3.125` without rounding; when converting to picodollars, v1 uses the old multiplier 1000 and v2 uses 100, both with BigInt before bounded aggregation. Do not apply v2 validation/units to persisted v1 cells or reprice old sums.

For complete single-tier/no-write models, calculate uncached input, cached read and output from explicit valid usage. Preserve `cachedRead <= input`; usage absence/overflow means unavailable. For DeepSeek retain lower/upper peak/off-peak range; do not select a tier without evidence. Qwen rows with Cached Write and/or context tiers live in the **same** v2 tariff snapshot but `referenceValue()` refuses a complete amount until both write count and any context tier can be proven; UI renders their official rate facts with a clear unpriced reason. This avoids a second tariff owner. No upstream price HTTP in the model request path. Bound persisted snapshot cells and update old-version validator/migration and operator docs if API shape changes.

Risk: new rate precision and strict historical snapshot validation may reject old metadata if changed in place. Test copied-data upgrade/restart with old versions and no bytes overwritten on malformed JSON; implement additive version handling. Rollback requires old version compatibility or a copied-data rollback rehearsal, not deleting statistics.
