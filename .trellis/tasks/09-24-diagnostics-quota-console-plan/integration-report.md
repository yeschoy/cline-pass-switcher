## Deployment preflight finding and safety correction (2026-09-25)

- User authorized pushing and deploying local `main` at `2a1b5fa`; it was pushed. The production container is limited to **512 MiB**. An isolated copy of the exact Compose-built candidate image `sha256:20306850c6b983a1caaec39490e8b55f3e2bc8f6fb0fd63a113bf8e8dfd1f2f1` passed startup on copied configuration, but six raw 35 MiB bodies **and** fifty sanitized 5 MiB bodies separately reproduced cgroup OOM (exit 137). **No production Compose switch was performed**; the old image remained healthy/zero-restart, current config bytes unchanged. Raw mode was false on the live baseline, but the shared 512 MiB budget alone made the sanitized error mode unsafe under pressure.
- The operator accepted a safety correction before deployment: restore a 64 MiB sanitized-subset cap in the same 512 MiB capture budget, and prevent the current 512 MiB environment from enabling raw capture. The new process-only `CLINE_PASS_RAW_BODY_READY=1` flag and detected ≥2 GiB limit are necessary, not sufficient, for future raw enablement; separate backup/rollback/load acceptance remains required. The current production Compose does not set this flag. Target-container revalidation and a new committed/pushed source/image are required before any live switch. This report is not a deployment-complete claim.
