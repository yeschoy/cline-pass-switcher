# Raw-detail candidate and production admission (local code candidate approved; live cutover not approved)

## Decision and release boundary

The operator rejected mixed sanitized-full/raw-error duplication. Keep three independently persisted booleans: `detailedLogging`, `errorDetailLogging`, and default-off `rawBodyLogging`. With raw off, preserve the existing sanitized full/error behavior. With raw on **and** initialized independent administrator **and** explicit `CLINE_PASS_RAW_BODY_READY=1` **and** detected >=2 GiB, select `raw-full` when full is on, else `raw-error` when error is on; both-on publishes only one full group. Error-only means real failed upstream attempts, even if a later attempt succeeds; it does not publish successful-attempt bodies. Both detail switches off means no capture. Unready persisted raw=true continues to suppress detail capture, not fall back to sanitized. The live baseline is `32a150e` with `{detailedLogging:true,errorDetailLogging:true,rawBodyLogging:false}`, 512 MiB and no readiness flag; changing settings there cannot provide the requested safe raw Header projection.

The operator chose the normal **committed `main`** source for a new code candidate. This includes already-pushed pricing and exclusive multi-client-key account ownership; its schema is not safe for direct old-image rollback. The operator approved local code-candidate implementation only, not a release or live raw enablement. Prepare a code candidate and independently review it; separately review an exact image/config/resource/cutover sheet before production mutation. Do not deploy a feature branch or working tree. Capture remains raw=false during build, migration rehearsal, release switch and acceptance until a later explicit cutover approval.

## Capture and trust boundaries

`server.js` remains the request-start profile selector and persist-first `/api/logs/settings` owner. `DetailRoot` in `lib/detailed-log-capture.js` remains the sole body/attempt capture owner; `DetailedLogStore` remains the only queue, inventory, manifest validator, retention and body-read owner. Preserve 35 MiB valid-UTF-8 raw body limit, 5 MiB sanitized limit, shared 512 MiB reservation/64 MiB sanitized fence, 1 GiB store, four admitted raw reads, 48h raw / 7d legacy retention, fail-open model traffic and no duplicate profile. These ceilings are **not** process RSS or guaranteed storage duration. Do not change transport bytes/status, provider retry/lease, SSE cancellation/first-event, statistics, ordinary JSONL or metadata to implement diagnostics.

Add a small **independently safe and bounded Header projection** to the raw manifest only, on the request plus failed/all attempt and downstream response boundaries appropriate to error/full profiles. Raw full includes ingress request, each real upstream attempt request/response and final downstream response Headers and existing bodies. Raw error includes only failed-attempt request/response Headers and their existing request/response bodies; no successful-attempt Header/body, no additional sanitized group, and no invented downstream response. Snapshot the needed Header maps while those native boundaries exist and release them at finalization; do not inspect a 35 MiB raw body to declare Header values safe. Build an allowlisted projection from bounded canonical Header names; reject/omit unsafe or excessive names/counts/bytes (including attacker-chosen credential-like names), render unknown values as `[REDACTED]`/omitted and permit a **small exact parser allowlist** of safe structural values only (for example, canonical media type without parameters or bounded decimal length). Never persist verbatim Authorization, Cookie, Set-Cookie, client/upstream/admin keys, proxy/CSRF tokens, arbitrary custom Header values, or credential-bearing URL text. Do not call the sanitized group-wide body redactor on raw text or reintroduce free-form account/model/provider/URL fields. Treat loss of fidelity as preferable to leaking a value. Precisely specify the final name/value allowlist in code/tests before implementation review.

Update `DetailedLogStore.validate()` raw request/attempt key allowlists and enforce the projection schema/limits **on publication and reads**; avoid accidentally rejecting previously valid raw groups with no Headers. Keep raw list/cursor/inventory summaries metadata-only, never include Header maps there. Detailed `GET .../<requestId>` alone may return the safe Headers to an independently authenticated administrator; body endpoint remains on-demand `text/plain` with `no-store`/`nosniff`. Prior old-image validators still reject raw profiles and do not traverse the raw child. Legacy sanitized records remain readable, and no existing groups are rewritten. Browser `public/index.html` renders safe Header maps in the selected detail metadata through `textContent` (not `innerHTML`), keeps raw body only in its current selected textarea, clears it on selection/navigation/logout/session loss/pagehide, and updates wording to distinguish safe Headers from unredacted bodies. A native one-time-per-enable risk confirmation must occur **before** posting raw=true; cancellation sends no write, and rerender/navigation must not silently opt in. Reuse existing generation and toggle owners; no second store or automatic body fetch.
