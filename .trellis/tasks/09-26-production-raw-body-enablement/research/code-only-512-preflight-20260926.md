# Code-only raw-off candidate at the existing 512 MiB limit — 2026-09-26

**Purpose/boundary:** separately test whether the already committed `main` image can start with raw disabled at the existing production cgroup limit; this is **not** a code deploy, paid upstream test, full-corpus load test or raw-admission result. A byte-identical `config.json`/`metadata.json`/`admin-auth.json` trio from the previously authorized root-private pre-upgrade rehearsal was copied to a new mode-0700/0600 private working directory. No production log/detail/raw body, account key or verifier value was printed or exported; Docker `--network none` and no published port prevented upstream traffic.

Exact Compose-built candidate image `sha256:f7c45edc2ccba0eab83baea36db65ffe70e4a19fd4c1b275b8fa6565f4e765bd` ran as UID/GID 1000:1000 with read-only root, dropped capabilities, no-new-privileges and tmpfs under **536,870,912 bytes**, with no `CLINE_PASS_RAW_BODY_READY` flag and raw=false. Isolated `/api/meta` returned 200. At the check it remained running with zero restarts/OOM kills; cgroup `memory.peak` was **53,993,472 bytes**. The ten existing stable accounts all normalized to `clientKeyId=legacy`, and the copied config SHA-256 matched the earlier isolated migration prediction `91a3480a7e3b3fc798df3a0be401c2b326525923592aab39b9bdc1089b86d0db`; raw remained false. The isolated container was stopped afterward; the live container was never switched.

This only proves **startup on the copied JSON trio**. The 927 MB live DATA_DIR corpus (ordinary and sanitized detailed logs), sustained chat/diagnostic traffic, quota scheduler contention, actual gateway/admin/browser reads, and a full production backup/rollback were **not** included. A 54 MB startup peak cannot be used as a 512 MiB production headroom guarantee. Pricing/client-key migration still makes direct old-image-on-v2 rollback unsafe. A separately reviewed **code-only raw-off** cutover could retain the present 512 MiB limit/absent ready flag *only after* a complete private pre-upgrade backup and exact rollback/acceptance gates; raw-on remains a later independently approved operation.
