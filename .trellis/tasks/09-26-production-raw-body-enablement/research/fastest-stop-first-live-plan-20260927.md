# Fastest safe stop-first raw-OFF code switch — read-only research (2026-09-27)

**Scope/evidence:** resolved active task with `task.py current --source`; inspected committed local helpers, reports and backend deployment/admin/client-key contracts; `git status --porcelain` was clean, local `main` and `origin/main` both `4d4ee8798f20a03e842d5cd52f21188bd1f0f88a` although the checked-out branch is `feat/raw-detail-safe-headers`. **No production connection or mutation in this research.** The reported production values below are historical observations, not a fresh live preflight. User now requests deployment restricted to code-only, raw=false, 512 MiB and no readiness flag; this is not permission for raw-on, memory increase, client-key/account edits or acceptance of the older release record.

## Decision: conditional GO for a manually owned stop-first window, NO-GO for immediate blind execution

The earlier UID-1000 parent refusal is **no longer a fundamental blocker**: committed `105c628` made `rollback_data_transaction.py` capable of a journaled, no-replace, same-device operational `/opt/cline-pass-switcher/data` v2→private-preserved-v2 then prepared-v1→active transaction. Isolated Linux tests covered a gap and a crash after the second rename; a full-copy test booted exact old image on renamed compatible v1 (`uid1000-rollback-linux-rehearsal-20260927.md`). This is a **library with no CLI/stop/fence/sidecar/Compose/start owner**, not an executable complete cutover or an automatic recovery daemon. The prior `backup_pause_window.py` and systemd watchdog are exclusively for pausing/unpausing the *same old container*; `backup_window.py` is explicitly retired. Do not run or adapt either for stop-first switch.

The helper is committed on the **task branch** (`105c628`), not in the allowlisted `main` release archive; its byte-identical root-private host copy, Python import directory and dependencies must be verified **before** stopping production. Do not assume the live host has this revision installed merely because the candidate application image exists.

Fastest route is **one bounded, operator-attended stop-first window with fail-closed manual recovery** using the already built committed-main candidate and committed copy/inventory/rename primitives, **after** the caller supplies a demonstrably continuous all-writers + ingress/in-flight fence and rehearses the missing stop/sidecar glue on a disposable full copy. No new scheduler or broad deployment framework is necessary; *independently supervised automatic old-image restart* is only required if promising bounded recovery after coordinator/SSH loss. The prior operator explicitly accepted that manual recovery of an ambiguous v2 state could exceed ten minutes (`code-switch-aborted-pre-mutation-20260927.md`); that does **not** authorize starting old on v2, writing despite an unfenced writer, or assuming a fixed outage bound. If the coordinator dies after an uncertain candidate `up`, hold ingress closed and request manual fenced recovery, not a timer-triggered old start.

### Minimum sequence (conditional plan, NOT a runnable command file)

0. **Before stop:** freeze and recheck full old container/image, project/Compose, runtime mounts, healthy/zero restarts/OOM, actual config/metadata/admin and four sidecar hashes, raw=false, empty raw child, 512 MiB/no ready flag; recheck exact archived `main` source `4d4ee87`, candidate Compose (only image/build-context delta), release-tree UID-1000-readable bytes/modes under its **UID-1000-owned** parent, exact prebuilt Compose image `sha256:bd49772e0a42a2f4f90bc35ce32408485d411caca46efe40c4b13c959105669d`, exact old image `sha256:0bd1deaefb04b6c2c3f1e3417eddc07b3fc6dd6398212ff98e6a783c3c62100c`. All IDs/hashes are historical until independently reread. On a *fresh* private config+metadata copy rehearse migration on this exact image and compare only allowed fields: stable ordered account IDs/all other fields, 32 Legacy owners only if the count is still 32, raw=false, admin unchanged; quota metadata timestamps are not a deterministic target hash. Preflight real helper/runtime availability, disk for **independent v1 + v2 + prepared-v1** copies and exact old/new image preservation. Prove no-op on pre-stop failure and atomic Compose install/restore on scratch.
1. **Fence first; then stop exactly old:** operator-controlled block of new model/admin ingress (public gateway **and** `ai-internal`/loopback/direct paths), wait for/drain or explicitly terminate in-flight work, and prevent *all* non-service writers of `DATA_DIR`, Compose, env, gateway and deployment sidecars through copy, start, validation and any rollback. Verify the fence actually excludes host jobs, root/UID-1000 processes, copiers and sidecar deployers and remains effective after SSH/coordinator failure. Docker stop or an FD sample does not establish this. Stop only the verified old service and prove it cannot restart or coexist with the candidate. The stop itself is the first live mutation; if timeout/identity is ambiguous, inspect and hold fenced, never assume a no-op.
2. **Fresh complete compatible v1 seal while stopped:** create a new root-owned/mode-0700 same-filesystem stage, not an old `trusted:false` backup nor the UID-1000 release parent. Reuse `backup_window_common.py`'s bounded `inventory(..., source=True)`/hash and authoritative `sidecars()` shape; use `rsync -a --numeric-ids --delete --delete-excluded --exclude=/detailed-logs/raw/***` **only into a new private copy**, rejecting symlinks, hardlinks and special entries and refusing any nonempty live raw child. Capture actual old Compose, env_file, resolved gateway target/link and deployment record; verify sidecar bytes/modes/owners, framed source→copy→source→final-source non-raw inventory, config/metadata/admin hashes. Make a separate restored v1 path, check full parity and boot exact old image against *that private restore* under 512 MiB hardening, then stop the test. Keep the live old stopped between seal and switch. If this fails before candidate Compose/up and active v1/old Compose are proved unchanged, restart **only that exact old container** and prove health/local route before releasing ingress; otherwise hold fenced.
3. **Install and switch with raw off:** durably phase-record the Compose-install and *possible-v2-write* `up` boundaries; atomically install only the reviewed two-field candidate Compose (fsync file/parent), check resolved project/image, use `docker compose up -d --no-build` and never build in-window. An unsuccessful/timed-out/lost `up` is **possibly v2**, even if the caller never observed healthy status. Keep the v1 seal immutable and all other writers fenced. Check exact running new image/source, zero restarts/OOM, 512 MiB, raw=false/no ready, fresh predicted config owner migration/admin parity and safe metadata paths; local `/api/meta`, then bounded public HTTPS/internal alias/model validation under controlled reopening of each route. Start with no paid upstream work. Only release each ingress path as deliberately validated; post-open traffic may write v2 logs/metadata. Record actual deployment as `awaiting-admin-acceptance` if protected views lack operator confirmation, never mark the older pending record completed by inference.
4. **On failure after possible v2 write:** close all ingress again, drain/stop the *exact candidate* and exclude every other writer. Seal a **different root-private full current v2 non-raw tree and matching current sidecars**, check source→copy→source, config hash and the unchanged v1 seal; reject unknown drift/raw groups. Decide whether any post-v1 operator/traffic writes can be lost or need reconciliation; **preserving v2 is necessary but does not silently authorize data loss**. Prepare another v1 restore in a root-private same-device path plus the helper's exact marker and `seal.json` (`version`, `v1`, `v1Config`, `v2`, `v2Config`) only after verified immutable seals. Supply a fresh exact candidate ID/image/exited probe and a separately verified sustained all-writers fence to `rollback_data_transaction.replace()`; inspect/resolve its phase journal with `recover_gap()` or `recover_active()` only in their documented exact states. This helper preserves live v2 via `renameat2(RENAME_NOREPLACE)` and installs verified v1; it neither restores sidecars nor starts Docker. Atomically restore **matching old Compose and, iff changed, matching old env/gateway/deployment state** with tested scratch restore/fence; verify complete active v1 + sidecars and isolate old management/raw paths **before** `up -d --no-build` exact old image. Verify old local/model path and deny client-key management from loopback/public/internal before reopening. Unknown phase, residual temp journal, changed tree/sidecar or missing fence => no old boot, retain both versions and escalate. Never `rsync --delete` onto the live tree or start old on v2.

## What is a hard block vs. deferrable evidence

| Item | Judgment |
|---|---|
| Continuous external/host writer and public/internal/loopback ingress/in-flight fence, with a named party able to keep it closed after SSH/coordinator loss | **Hard pre-stop block**, not solved by stop, operator testimony, FD scan, hash, Docker mount inspection or UID-1000 directory FD. Without it, the rename helper's checks can race a same-UID writer and v1/v2 seals can drift. Need a concrete verified control/rollback owner. |
| Fresh root-private full v1+sidecar seal bound to this stop; current migration prediction; separate complete v2 seal before *any* v1 restore; raw empty/excluded | **Hard**; old resumed service makes the earlier 2,355-entry backup stale even if `config.json` hash still matches. No original bytes may be overwritten on drift. |
| Exact committed `main` archive/image/release parent, Compose-only delta, 512 MiB/raw=false/ready absent, and safe old-image management ingress | **Hard to check** at window; historical image/hash and three client-key 401 routes are not fresh provenance or proof of positive login/every reachable peer. Existing exact old image supports raw manifests; this raw-off sequence requires raw child empty/isolated. |
| Compose/sidecar atomic restore + verified stopped-candidate callback + installed helper invocation/recover phase on a disposable copy | **Hard rollback readiness**; no existing production CLI orchestrates them, and rename tests alone do not exercise recovery of Compose/env/gateway/deployment after coordinator loss. Manual commands are acceptable only after rehearsed, reviewed gates; fail closed on ambiguity. |
| Independent persistent stop/start watchdog and guaranteed ten-minute availability | **Not a universal hard requirement** if a truthful unbounded manual recovery risk is accepted. A fail-closed, durable phase record and human on call can prioritize data safety; do not reuse pause watchdog or promise automatic restoration. |
| Positive independent admin Cookie/CSRF from public gateway | **Hard to claim authenticated acceptance** and must have a practical operator check plan before switch. Deployment spec permits a healthy machine-verified code release to remain `awaiting-admin-acceptance` if operator-only protected views are outstanding; negative 401 is not a positive check. Proven failure with an available admin session is a rollback gate. |
| >=2 GiB load, external raw backup TTL, raw real-browser UI and older 2026-09-24 release acceptance | **Not prerequisites of this raw-off/512 MiB code-only switch**; still hard prerequisites before any raw-on cutover, and the older release record stays separately pending. |

**Minimum genuine operator question if the fence cannot be proven read-only:** who controls the public **and internal/direct** request paths and every host/external `DATA_DIR`/sidecar writer, and can that person enforce a stop/drain/write freeze that remains in force if the deploy coordinator disconnects? Without a verifiable mechanism and named recovery owner, answer is **NO-GO before stopping** despite the user's deployment instruction. This research does not assert the fence exists or ask for another generic deployment assent.
