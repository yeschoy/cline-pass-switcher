# 增强错误规则与可视化编辑器

## Goal

让运维人员无需手写 JSON 即可安全管理状态码和失败内容规则，同时保留高级批量编辑能力及现有状态码规则兼容性。

## Background

- 当前 `accountErrorRules` 仅支持精确状态码到 `ignore/cooldown/ban`，UI 是三行高级 JSON textarea。
- 用户已确认采用“可视化规则表格 + 可折叠高级 JSON”，两者必须共用同一草稿。
- 用户已确认内容规则匹配完整、有界、已脱敏的规范化错误信息，包括嵌套 `message/code/type`。
- 非流式和首包前 SSE 已在处置前归一化失败；首包后 SSE 只能更新未来账号状态，不得重放。

## Requirements

### R1 — 兼容内容规则 schema

- 既有 `accountErrorRules` 原样兼容，无需迁移。
- 新内容规则使用独立持久字段；旧客户端省略时服务端保留当前值，避免完整账号保存意外清空。
- 内容规则数组有显式顺序；每条包含普通文本关键词、可选归一化状态范围、动作和可选冷却时间。
- 严格限制规则数、关键词长度、总字节、状态范围和 cooldown；未知/缺失字段全部拒绝且不保存。

### R2 — 匹配语义

- 仅对已归一化为失败的响应执行大小写不敏感普通文本包含；不支持正则、不包含或 JSONPath。
- 匹配输入为完整规范化错误信息，保留嵌套诊断字段，但在匹配前脱敏配置 Key、代理/Header 值及当前请求消息，并限制长度。
- 按数组顺序首条内容规则命中即生效；未命中才回退既有状态码规则。
- 内容 `ignore` 阻止状态规则继续处置，但不改变既有 provider failover 语义。
- 不持久化或展示原始响应体、规范化匹配全文、关键词命中片段或敏感数据。

### R3 — 流式/换号安全

- 非流式和首包前 SSE 可按既有规则最多更换一次账号。
- 首包后 SSE 命中规则只改变未来账号状态；不得重放当前请求。
- 客户端取消不执行内容规则，不产生错误日志/健康处罚。

### R4 — 可视化与高级 JSON

- 可视化表格支持新增、编辑、删除和内容规则排序；使用有标签原生控件、上下移动按钮及 aria-live 反馈。
- 高级 JSON 位于可折叠区域，显式“应用到草稿”；编辑期间可视草稿变化时必须检测 stale，不能静默覆盖。
- 可视化和 JSON 都只修改一个错误规则 draft；普通 `saveAccounts()` 才持久化。
- 现有预设继续操作状态码规则；合并/替换/清空状态规则时默认保留内容规则。
- 搜索、账号表重绘、抽屉、批量编辑、统计/日志导航必须保留规则草稿和暂时非法的高级 JSON 文本。

## Acceptance Criteria

- [x] 旧 `accountErrorRules` round-trip 和运行行为完全兼容；旧客户端保存不清空内容规则。
- [x] 内容规则首条匹配、状态范围、ignore 终止和状态规则回退均有黑盒测试。
- [x] 嵌套错误诊断可匹配；Key、代理/Header、消息和原始响应体不进入配置外的持久诊断或 UI。
- [x] 非流式、首包前 SSE、首包后 SSE、provider retry、账号替换和取消行为可执行验证。
- [x] 日常规则可完全通过可视化表格编辑；高级 JSON 往返无损且 stale/invalid 不覆盖新草稿。
- [x] 预设、完整账号保存和所有其他账号草稿字段保持完整。
- [ ] UI/VM、integration 和完整项目门禁已通过；真实浏览器键盘/焦点/窄屏检查因 browser binary/Accessibility 基础设施阻塞而未验证，见 `research/verification.md`。

## Out of Scope

- 不支持正则、不包含、JSONPath、任意脚本或成功响应扫描。
- 不保存规则命中正文证据。
- 不改变账号选择算法、provider 尝试顺序或首包后重放禁令。
- 不引入第三方规则引擎或前端框架。
