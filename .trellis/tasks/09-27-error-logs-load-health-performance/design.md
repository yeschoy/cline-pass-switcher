# Cross-deliverable design and integration gates

The parent owns no business-code implementation. Its children own: (1) error-log same-section captured-detail viewing, (2) opt-in non-sticky load/health routing plus a separately configurable **pure concurrency full-pool** wait, (3) a differential high-concurrency investigation. Each child has its own `design.md` and `implement.md` and may be started, checked and archived independently.

Preserve a shared security and compatibility boundary: ordinary JSONL stays a bounded sanitized projection; raw details require the existing authenticated opt-in store and safe Header projection; `raw-full` is not switched on in production by a UI change. Routing retains client-key ownership, per-account RPM/concurrent admission, sticky bindings and post-lease Provider retry. Config/UI round-trip and old-client saves must not mutate the new field unintentionally. Performance work is local and synthetic and does not deploy or automatically authorize an optimization.

Ordering: first implement and verify the error viewer and routing separately; performance baseline may run before them but the *comparative* measurements must use the verified integrated source and describe revision differences. Run relevant narrow suites, full project gate, and real-browser checks for visual/focus interactions, then perform a final cross-child review. Rollback is component-wise: remove inline viewer without changing detailed storage; select a legacy account mode and reset `poolFullWaitMs` to inherited; retain only reviewed, non-secret performance research. Production activation is explicitly outside this task.

Review assumptions before activation: error rows reveal only one selected request's raw body on a second explicit click, not automatic page-wide text; new load-health mode applies only with sticky disabled (sticky first misses stay unchanged); `poolFullWaitMs` is for pure all-finite concurrent saturation, not RPM-only/mixed. During a transition between selected-account and pool-full blocking, both deadlines use the original admission start, never sum two full timeouts.
