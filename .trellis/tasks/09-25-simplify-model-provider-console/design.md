# Browser console design

Reuse `MODEL_PROVIDER_DATA`, `MODEL_PROVIDER_QUERY_ID`, `MODEL_PROVIDER_CONTROLLER`, `api('/api/statistics')` and `renderModelProviders()` in the inline production script. Add a feature-local selected subview, not a generic client store. A single accepted `/api/statistics` snapshot drives both model and Provider projections; only refresh fetches, search/tab changes re-render locally. Filter model tab on model ID; Provider tab on Provider/model names with an explicit unknown-Provider group per model. Keep one real table per selected view or shared table with context-specific headers and accessible `aria-controls`/selected state. The first tab is model, maintain focus return and a succinct live status on selection; preserve top-level nav focus behavior.

Default model columns: resolved model, `请求成功率`, compact explicit usage/cache, `参考用量等值` or unavailable. Provider columns: model / channel, `渠道尝试成功率`, final-success attributed usage/cache and comparable reference amount; label that the success denominator is **attempts** but usage denominator is final successful requests. Exact covered counts, old price versions/tariffs, unknown-vs-zero and migration dates remain in expandable semantic `<details>` outside crowded cells or per-row (keyboard operable), escaped or `textContent`; do not populate raw HTML with untrusted model/Provider text. Cost is reference, not a subscription charge. No new API/store is needed unless the pricing child supplies additive rate facts.

The parent price child can complete first; UI tests should also work against an old four-model snapshot. Keep the existing generation/abort checks in success/catch/finally and authenticated account drafts unchanged. Compare a 390 CSS px real-browser screenshot/scroll/focus flow to existing baseline; VM tests alone do not prove layout.
