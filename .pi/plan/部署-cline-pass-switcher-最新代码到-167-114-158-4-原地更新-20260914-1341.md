## 实施步骤

### 1. 本地打发布包（不改工作区）

用 `git archive` 从 HEAD 打包部署所需文件（自动排除 `._*` AppleDouble 残留与 `.trellis/.pi` 等无关目录）：

```bash
REL=20260914-0540-stats-pipeline
git archive --format=tar --output="$PI_SCRATCH_DIR/$REL.tar" HEAD \
  Dockerfile package.json package-lock.json server.js lib public README.md LICENSE \
  .dockerignore config.example.json
shasum -a 256 server.js public/index.html   # 记录基准值
```

期间可选：`node smoke.mjs .`（用 `data/deployment/20260913-02538a3/smoke.mjs`）在本地对 HEAD 做一次 mock 上游冒烟。

### 2. 上传并落到 releases（不触碰 data/）

```bash
scp -i ... -P 49555 "$PI_SCRATCH_DIR/$REL.tar" ubuntu@167.114.158.4:/tmp/
ssh ... 'mkdir -p /opt/cline-pass-switcher/releases/'"$REL"' && tar xf /tmp/'"$REL"'.tar -C /opt/cline-pass-switcher/releases/'"$REL"' && rm /tmp/'"$REL"'.tar'
# 校验落地文件 sha256 与本地一致（server.js / public/index.html）
```

### 3. 备份与切换 compose

- 复制 `compose.yml` → `compose.yml.before-<REL>`（沿用既有命名习惯）；
- 复制 `deployment.json` → `verification/deployment.json.before-<REL>`；
- 在 `verification/backup-<ts>/` 留存 `config.json`、`metadata.json` 副本（只读备份，不修改原文件）；
- 仅改两处并写回 `compose.yml`（保持 0600 权限、其余字段逐字不变）：
  - `image: cline-pass-switcher:<REL>`
  - `build.context: ./releases/<REL>`

容器 **保留**原有硬化配置：`user 1000:1000`、`read_only`、`cap_drop [ALL]`、`no-new-privileges`、`pids_limit 64`、`mem_limit 512m`、`cpus 1.0`、`tmpfs /tmp`、`healthcheck`、`restart: unless-stopped`、json-file 日志轮转、`ai-internal` 网络与别名。

### 4. 构建并原地更新

```bash

```

预期构建会拉取 `node:22-alpine`（服务器首次），随后 `npm ci --omit=dev`。

### 6. 失败与回滚

- 任一步失败即停在原状：恢复 `compose.yml.before-<REL>` → `docker compose up -d`（旧镜像 `20260914-004157-full-errors` 仍在本地，**不清理任何旧 release/镜像**）；
- 回滚后旧代码不识别 `statistics` 键，仅影响统计视图，账号/路由配置零影响；
- **不做**的清理动作（留待你单独确认）：3 个 Exited 的 smoke 容器、8.39GB 镜像与 4.65GB 构建缓存。

## 风险与取舍

- 更新期间有**约 10–60 秒**的服务中断（停止旧容器→新容器 healthy），符合你「不考虑灰度、直接更新」的要求；
- 首次构建需在服务器拉取 `node:22-alpine`，若拉取慢会拉长窗口；若拉取失败则整体中止并回滚，不改变线上状态；
- 新代码启动即按新 schema 重写 `metadata.json`（统计结构升级），这是**单向迁移**；回滚时统计视图会退化为 legacy 基线，属预期行为。
